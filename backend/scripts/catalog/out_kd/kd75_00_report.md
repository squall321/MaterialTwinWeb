### 읽을 것 셋

1. **전역 비율은 10.5% 로 JA 의 15.7% 보다 낮다.** 구멍은 PCB 6도메인에 몰려 있는 게 아니라 **오히려 그 반대다** — 가장 심한 곳은 `smart_device_tech`(30.4%) · `eda`(30.2%) · `smartphone_systems`(27.8%) · `smartphone_pcb`(26.3%) 로, 전부 **작고 최근에 만든 도메인**이다. 큰 도메인(`oss_solver_docs` 0.1% · `metrology_catalogs` 1.8% · `product_data` 0%)은 거의 멀쩡하다.
2. **절대 수로는 `standards_appnotes` 가 가장 크다** — 2,483장이고 그중 **2,453장이 0바이트**다. 이 도메인의 「캡션만」은 사실상 전부 **완전 공백**이다. 규격·앱노트는 표가 많고 레이아웃이 험해서 docling 이 통째로 포기한 것으로 보인다.
3. **0바이트가 4,171장 — 캡션만 남은 표의 45%다.** 이건 「캡션만」이 아니라 **아무것도 아닌 것**이다. 캡션이 없으면 **무엇을 잃었는지조차 모른다** — 표적을 고를 단서가 0 이다. 이 45%는 원본 PDF 를 열기 전에는 분류도 불가능하다.

### JA 의 3,584 와 내 2,465 가 왜 다른가 — 재현해 봤다

같은 6도메인에 내 판별을 걸면 이렇게 나온다.

| A. `\|` 0개 | 2,465 |

**어느 판별로도 3,584 가 재현되지 않는다.** 가장 가까운 것이 「파일 300 B 미만」(3,811)과 「데이터행 ≤ 2」(3,980)다. JA 가 쓴 판별은 보고서에 적혀 있지 않아 확정할 수 없다. **이 보고서의 숫자는 전부 판별 A(`\|` 0개)이고, 기준을 위 표에 노출해 둔다** — 다음 파동이 또 재현을 못 해 헤매지 않도록.

## ⑤ `|` 유무로 가르는 것이 옳은 판별인가 — **아니다. 두 겹이 새고, 한 겹은 과잉이다.**

브리프의 물음이다. 여섯 판별을 코퍼스 전역에 다 걸어 봤다.

| 판별 | 적중 | 전체 대비 |
|---|---:|---:|
| **A. `\|` 가 하나도 없다** (브리프의 판별) | 9,327 | 10.5% |
| B. 데이터행이 0 | 9,343 | 10.5% |
| **C. 셀은 있는데 숫자 셀이 0** | **13,639** | **15.4%** |
| D. 0바이트 | 4,171 | 4.7% |
| E. 비어 있지 않은 줄이 1개 이하 | 9,332 | 10.5% |
| G. 데이터행이 1개 이하 | 11,209 | 12.6% |

### 새는 데 셋

1. **`|` 가 있어도 숫자가 없으면 물성 출처가 못 된다 — 4,312장을 A 가 놓친다.** 예: `standards_appnotes` 에 `| Samsung | Samsung |` 만 27~53바이트로 남은 파일이 무더기다. 이건 표가 아니라 머리글 조각이다. **판별 C 가 A 를 포함하고 4,312장을 더 잡는다.**
2. **`|` 가 있고 숫자도 있는데 표가 아닌 것.** 예: `Ehrler 2002 / table-2.md` 는 `| Sylvia Ehrler ... | / | Circuit World 28/4 [2002] 38-45 |` — **머리글·꼬리글이 표로 잡힌 것**이다. 숫자 셀이 1개라 C 도 통과한다. 판별 **G(데이터행 ≤ 1)** 를 함께 봐야 걸린다.
3. **표가 아닌데 표 파일로 들어온 것 — 그림 캡션이다.** 위 ④(나)에서 셋을 실물로 밟았다: `Tz-Cheng Chiu 2011 / table-4.md` = `Fig. 11. Storage modulus master curve...`, `Horiki 2011 / table-2.md` = `Fig.11. Test structure and design`, `Perkins 2009 / table-39.md` = `Fig. 8.2 ...`. **이건 「잃은 표」가 아니라 「애초에 표가 아니었던 것」이다.** 캡션만 표를 세면 여기가 분모를 부풀린다.

### 과잉인 데 하나

4. **숫자가 없는 표가 다 고장 난 것은 아니다.** `Table 2 Comparison with state-of-the-art methods`(정성 비교표) · `Table 4 - Qualitative Reference for Self-Assessment` 처럼 **원래 글자만 있는 표**가 C 에 섞인다. C 를 그대로 쓰면 고장이 아닌 것을 고장으로 센다.

### 그래서 제안하는 판별 — **한 축이 아니라 네 갈래로 분류해라**

```
0바이트            → "무엇을 잃었는지도 모른다"  (4,171장, 45%) ← 표적 선정 불가, PDF 를 열어야만 안다
캡션만(|=0, >0B)   → "캡션은 남았다"            (5,156장)      ← 캡션으로 표적을 고를 수 있다
셀은 있고 숫자 0   → "숫자만 잃었거나 원래 정성표" (4,312장)    ← 캡션+행이름으로 갈라야 한다
데이터행 ≤ 1       → "머리글/꼬리글/그림 캡션일 가능성"        ← 표적 목록에서 먼저 걸러라
```

그리고 **표적을 고를 때는 캡션이 아니라 `figures.json` 과 대조해라.** 그림 캡션이 표 파일로 들어온 경우가 실제로 있으므로, `head` 가 `Fig.` / `그림` 으로 시작하면 표적에서 빼야 한다. 이 배치의 `kd75_02_priority_targets.csv` 498장에는 아직 그 필터가 안 걸려 있다(정직하게 적는다) → 인계 5번.

**한 줄로 줄이면 — `|` 유무는 필요조건이지 충분조건이 아니다. 「표 층에 없더라」는 두 가지가 아니라 다섯 가지다.**
