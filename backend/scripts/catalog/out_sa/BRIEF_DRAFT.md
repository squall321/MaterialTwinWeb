## (초안 1) packaging 빈칸 443개를 분해했다 — 진짜 남은 것은 192칸이다

§582(packaging 444칸 · 53차 OC)·§584(pcb 391칸)·56차 RD(thermal 110칸)의 네 번째 실행이자,
**§582 가 처음 갈랐던 그 계통을 판정 칸으로 옮겨 닫은 실행**이다.

| | 전 | 후 |
|---|---:|---:|
| 재료 · 칸 | 116 · 812 | 116 · 812 |
| 채움 | 369 (45.4%) | **389 (47.9%)** |
| V1 해당 없음 | 0 | **21** |
| V2 벤더·출처 구조적 부재 | 0 | **184** |
| V3 자유 키 판정 | 35 | **0** |
| V4 등급 미확정 | 24 | 24 |
| V6 인쇄됐으나 기각 | 0 | **2** |
| **V5 진짜 남은 것** | **384** | **192** |

**전 계통 최악이던 384칸이 192칸으로 줄었는데, 그중 값으로 준 것은 20칸뿐이다.**
나머지 172칸은 문서를 열어 "없다"를 확인한 결과다. §582 가 이 계통을 이미 갈라 두고도
V5 가 384로 남아 있었던 이유는 **판정을 적을 자리가 아니라 판정을 옮길 사람이 없었기 때문**이다 —
§593 이 magnetics 에서 말한 것과 같은 모양이 packaging 에서도 그대로 있었다.

문서 **12장**(벤더 시트 10 · 편찬표 2)과 **논문 10편**을 실제로 열었다(§127).

## (초안 2) V4(등급 미확정) 판정은 운영까지 가지 않는다 — 집계가 읽는 칸과 병합기가 옮기는 칸이 다르다

§582 의 V4 는 `attributes.anonymised_code` 나 `attributes.identification_status` 가 '미식별' 로
시작하는지로 정해진다(`coverage_report.subsystem_core`). 그런데 병합기의 큐레이션 전파는

```python
CURATION_KEYS     = {"role","role_reason","role_basis","role_confidence","subsystem","subsystem_basis"}
CURATION_PREFIXES = ("core_", "merge_", "same_alloy_", "verdict_")
```

뿐이다 — **`identification_status` 도 `anonymised_code` 도 여기 없다.**
즉 dev 에서 "이 재료는 등급이 원리적으로 안 닫힌다"고 판정해도 그 판정은 운영 DB 에 영영 안 간다.
V1·V2 는 `core_` 접두어라 가는데 V4 만 못 간다.

- 이번에 V3 35칸(616 실리콘 포팅 1종 · 2305~2308 Palaniappan 언더필 A/B/C/D 4종)은
  **성격상 전부 V4**였다. 그런데 V4 자리에 적으면 운영에 안 가고, `core_fill_sheet` 같은 자유 키에
  적으면 집계가 못 읽는다(§593). 그래서 **전파되는 `core_absent_from_vendor_sheet` 에 적고
  사유 문장 안에 "성격상 V4 다"를 못박았다.** 통계는 V2 로 세어지지만 근거는 남는다.
- **고칠 자리는 둘 중 하나다** — 병합기의 `CURATION_KEYS` 에 `identification_status`·`anonymised_code` 를
  더하거나, `core_grade_undetermined` 같은 `core_` 접두어 칸을 새로 내고 집계를 그쪽으로 옮기는 것이다.
  채굴 배치가 공유 도구를 고치면 안 되므로(§468) 신고만 한다.

## (초안 3) `apply_core_verdicts.py` 는 한 재료에 판정 행을 둘 내면 뒤엣것이 앞엣것을 덮는다

56차 RA 가 굳힌 `scripts/catalog/apply_core_verdicts.py` 가 시작할 때 `material.attributes` 를
**한 번만 읽어 dict 로 캐시**한다. 그래서 같은 `material_id` 로 판정 행을 둘 내면
(예 — 재료 1356 에 `core_absent_from_vendor_sheet` 4칸과 `core_rejected_printed_value` 1칸을 따로 냈다)
**뒤 행이 앞 행의 병합 결과를 통째로 덮는다.**

```
행 둘로 냈을 때 : DB 에 core_rejected_printed_value 만 남고 core_absent_from_vendor_sheet 4칸이 사라짐
한 행으로 합쳤을 때 : 둘 다 들어감
```

조용히 사라진다 — 도구가 "병합 44 · 재료 44" 로 성공을 찍는다.
집계를 다시 세어 **선언 184칸 대 집계 180칸**이 어긋난 것으로 잡았다.

**규율 — 한 재료의 판정은 한 행에 담아라.** 그리고 **판정을 박은 뒤에는 반드시 집계를 다시 세서
선언한 칸 수와 맞는지 대 봐라**(§129 의 행 배정 검산을 판정에 적용한 것이다).
도구 쪽 고침은 `attrs` 를 행마다 다시 읽거나 `material_id` 로 먼저 합치는 것인데, 공유 도구라 신고만 한다.

## (초안 6) Indium Corporation 자사 편찬표가 패키징 솔더 코어를 연다 — 순금속 넉 줄이 표 전체를 검산하고, 딴 벤더표가 인장강도를 0.5% 안에서 확인한다

56차 RD 가 Wayback CDX 로 찾아낸 `alloy_sorted_by_indalloy_number.pdf`(2006, Indalloy 250여 등급)를
packaging 솔더에 다시 썼다. §129 의 실행이다.

**① 표 전체를 순물질 행으로 검산했다.**

| 행 | ρ (g/cm³) | k (W/m·K) | CTE (ppm) | E (GPa) | Cp (J/kg·K) | UTS (MPa) |
|---|---|---|---|---|---|---|
| 100.0 In | 7.31 (7.31) | 86 (81.8) | 29 (32.1) | 10.8 (11) | 243 (233) | 1.88 (~2.2) |
| 100.0 Sn | 7.28 (7.31) | 73 (66.6) | 24 (22) | 42.1 (~50) | 222 (228) | 13.1 (~15) |
| 100.0 Pb | 11.35 (11.34) | 35 (35.3) | 29 (28.9) | 18.0 (16) | — | 12.4 (~12) |
| 100.0 Ag | 10.50 (10.49) | — | — | — | — | — |

괄호가 교과서값이다. 네 줄이 다 맞으므로 열 배정과 단위 환산이 동시에 닫힌다.

**② 열 배정은 문자 위치가 아니라 `pdftotext -bbox-layout` 의 단어 x좌표로 했다.**
`-layout` 텍스트는 **행마다 들여쓰기가 11자까지 밀린다**(조성 열의 원소 수가 달라서다).
그 상태로 열을 자르면 비열 SOLID 와 LIQUID 가 뒤바뀐다. bbox 로 재면 SOLID 머리글 중심이 x=706,
LIQUID 가 x=726 이고 값이 x=712 라 갈린다. **§41 의 pdftotext 판이다 — 편찬표는 bbox 로 읽어라.**

**③ 딴 벤더표가 인장강도를 독립 확인한다.** The Solder Connection 사양표(2023)의 `kgf/cm²` 열과
Indalloy 의 `PSI` 열이 서로를 검산한다.

```
Sn63Pb37   Indalloy 7,500 psi = 51.7 MPa  ·  SC 525 kgf/cm2 = 51.5 MPa
Sn60Pb40   Indalloy 7,600 psi = 52.4 MPa  ·  SC 535 kgf/cm2 = 52.5 MPa
Pb92.5Sn5Ag2.5  Indalloy 4,210 psi = 29.03 MPa · SC 295 kgf/cm2 = 28.9 MPa
Pb90Sn10   Indalloy 4,400 psi = 30.34 MPa · SC 310 kgf/cm2 = 30.40 MPa
```

**④ 그러나 §129 의 '밀도만 재현된다' 는 여전히 살아 있다.** 같은 두 표가
`Sn96.5Ag3.5` 에서 밀도 7.50 대 7.37 · 열전도율 33 대 55 · 인장강도 40.0 대 56.9 MPa 로 갈린다.
**한 합금 계열에서 네 칸이 맞았다고 표 전체를 믿으면 안 된다 — 행마다 대 봐라.**

## (초안 7) 편찬표의 탄성계수 한 칸이 **혼합물 하한** 아래로 떨어졌다 — 92.5Pb5Sn2.5Ag

Indalloy 151 행(92.5 Pb / 5.0 Sn / 2.5 Ag)의 `Young's Modulus` 는 **2.0 × 10⁶ psi = 13.8 GPa** 다.
같은 표의 순 Pb 가 2.61(18.0 GPa) · 순 Sn 6.1(42.1) · Ag 는 83 GPa 급이다 —
**모든 성분보다 낮다.** 부피분율(Pb 0.898 · Sn 0.0755 · Ag 0.0262)로 Reuss 하한을 재면 **19.2 GPa** 라
인쇄값이 28% 아래다. §25(Manikam 의 CTE 가 모든 성분보다 낮았다)와 같은 위반이다.

같은 표의 Pb-Sn 계열이 Sn 함량에 대해 E 가 단조증가하는 것도 이 한 칸만 어긋난다 —
`순 Pb 2.61 → 90Pb10Sn 2.76 → 80Pb20Sn 2.90 → 70Pb30Sn 3.05 → 60Pb40Sn 3.34 → 순 Sn 6.1`.

**그 칸만 버리고 같은 행의 비열 0.13 J/g·°C 와 인장강도 4,210 psi 는 넣었다**(§141).
기각은 `attributes.core_rejected_printed_value` 에 적어 V6 으로 세어지게 했다 — 다음 파동이 같은 칸을 다시 캐지 않는다.
비열은 Kopp-Neumann 질량가중 136.6 J/(kg·K) 와 5% 안이고, 인장강도는 딴 벤더표와 0.5% 안이다.
**한 행이 통째로 죽는 것이 아니라 한 칸만 죽는다** — 그 칸을 가르는 것이 계열 단조성과 혼합물 하한이다.

## (초안 8) 표의 `n` 열을 포아송비로 읽지 마라 — 0.5 를 넘으면 그것만으로 다른 물리량이다

Hohlfelder 2001 TABLE I 이 언더필·BCB 의 `σys / σUTS / E / **n** / εpl / KIc` 를 인쇄한다.
`n` 열은 Zymet 0.62 · Dexter 0.77 · BCB-hard 0.68 이다.

**등방재의 포아송비 상한은 0.5 다.** 세 값이 다 넘으므로 이 열은 포아송비가 아니다
(적재기의 `RANGE["mechanical.poisson_ratio"] = (-1.0, 0.5)` 가 넣으려 해도 막는다).
그런데 표의 열 이름이 `n` 이라 사람 눈에는 ν 로 읽히고, **언더필의 ν 는 카탈로그에서 가장 비어 있는 칸이라
찾는 사람이 반가워할 자리**다. 그래서 판정 사유에 verbatim 으로 못박아 두었다.

**§443 의 반대 방향 용법이다** — 물리 위반이 표를 죽이는 게 아니라, 물리 위반이 **열의 정체를 밝힌다.**

## (초안 9) 같은 표 안의 두 삼각검산이 갈리면 안 닫히는 쪽 한 칸만 죽는다 — Wang 1993 인장탄성률

IBM Endicott C4 봉지재(Wang & Papathomas 1993) 기계물성표가
`굽힘탄성률 9.72 GPa · 굽힘강도 82.0 MPa · 파단변형 0.85% · 인장탄성률 16.6 GPa · 인장강도 65.5 MPa · 연신 0.53%` 를 인쇄한다.

```
굽힘  82.0 MPa / 0.85% = 9.65 GPa  대  인쇄 9.72 GPa   → 0.7% 안, 닫힌다
인장  65.5 MPa / 0.53% = 12.36 GPa 대  인쇄 16.6 GPa   → 34% 어긋난다
```

그리고 등방 충전 에폭시에서 인장탄성률이 굽힘탄성률의 1.7 배가 되는 것도 이상하다.
**인장탄성률 한 칸만 버렸다**(§35·141). 굽힘 두 칸과 인장강도·연신은 그대로 둔다.

이 칸과 초안 7 의 92.5Pb5Sn2.5Ag 영률, 둘 다 57차 SD 가 새로 낸 **V6(인쇄됐으나 기각)** 에 적었다 —
56차 RA 초안 C 가 요청한 자리가 같은 파동에 열려 첫 두 사용자가 되었다.

## (초안 10) 벤더표의 약칭이 통용 약칭과 다르다 — `SAC0107` 은 `SAC107` 이 아니다

The Solder Connection 사양표가 `Sn99.2Ag0.1Cu0.7` 에 **(SAC0107)** 이라고 괄호를 단다.
카탈로그의 재료 986 `SAC107 Solder Alloy` 는 원문(Chen 2020) verbatim `Sn-1Ag-0.7Cu (SAC107)` 다 —
**Ag 가 0.1 대 1.0 으로 열 배 다르다.**

같은 표에 `SAC0307`(Sn99Ag0.3Cu0.7) 과 `SAC0807` 도 있어, 이 표는 **앞 두 자리를 Ag 의 소수점 이하로 쓴다.**
통용 약칭(SAC105 = 1.0Ag 0.5Cu · SAC305 = 3.0Ag 0.5Cu)과 규칙이 다르다.

**§48(동음이의)의 벤더표판이다 — 괄호 안 약칭이 아니라 조성 열로 행을 골라라.**
재료 585 `Sn0.3Ag0.7Cu` 는 조성이 SAC0307 과 글자 단위로 같고 밀도 7.33 이 카탈로그 기존값과 일치해서 닫혔다.

## (초안 12) FE 입력표의 포아송비가 **원문 자신의 Prony 계수로 세 자리까지 검산된다** — §3 의 출구

Chiu 2018(fan-out WLP 재구성 웨이퍼 워피지) Table 6 은 이름부터
`Elastic material properties for the reconstituted wafer` 라 §3(FEA 입력표의 값은 실측이 아닐 수 있다)의 정중앙이다.
그런데 같은 논문 Table 3 의 유리상 계수가 그 값을 만든다.

```
Eg = 26.3 GPa · Gg = 9.59 GPa · Kg = 34.0 GPa
nu = E/(2G) - 1        = 26.3/(2 x 9.59) - 1        = 0.3712
nu = (3K - E)/(6K)     = (3x34.0 - 26.3)/(6x34.0)   = 0.3711
Table 6 인쇄값                                        = 0.371
```

**두 독립 관계식이 인쇄값과 세 자리까지 같다.** 저자가 E'(ω)·G'(ω) 마스터커브를 동시 피팅하면서
ν 를 0~0.5 로 구속했다고 본문이 밝히므로, 이 값은 인용도 관례값도 아닌 **저자 자신의 측정에서 나온 것**이다.
저자가 계산한 값이라 `method="computed"` 로 넣었다(§43 의 역산 금지선 안쪽이다 — 우리가 나눈 것이 아니다).

**§3 을 좁힌다 — FE 입력표라도 같은 논문의 다른 표가 그 값을 재구성하면 그것은 실측 계보다.**
