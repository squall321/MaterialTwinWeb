## 1. 표적 (5)·(7) — 그림이 벡터였다
`bjr004010.pdf` 는 `pdfimages -list` 가 0장을 돌려주는 **벡터** PDF 였다(Acrobat PDFWriter 4.0 / 橡応力緩和.xls).
그래서 `digitize_curve.py` 를 쓰지 않고 콘텐츠 스트림에서 마커 좌표를 직접 뽑았다(`ad_jcba_relax_extract.py`).
- 축 보정 — 가로 격자 10개(0~100 %) · 십년눈금 4개(1·10·100·1000 h). x(2)=x0+W·log10(2) 로 자기검산.
- 계열 동정 — **색으로 하지 않았다.** 범례를 읽어 `(마커 색, 모양) → 계열명` 표를 파일마다 만들고,
  데이터 마커를 **그린 순서**로 끊어 여섯 묶음을 범례 여섯과 순서대로 짝지어 단언했다.
  120 ℃ 판은 두 T.D. 계열이 같은 파란 막대라 색만으로는 못 가른다.
- 값의 성격 — 원문은 `応力緩和率`(= δt/δ0×100, bjm004 식 4-3)이고 카탈로그 키는 유지율이라 `1-x` 를 넣고
  인쇄값을 `conditions.printed_value_pct` 에 남겼다. 재료 92 의 같은 변환 계보를 따랐다.
- 렌더 확인 — `pdftocairo -r 190` 으로 C1720 150 ℃ 판을 눈으로 봤다. 1000 h 끝점이 21 %(추출 21.25) ·
  17 %(16.99) · 9 %(9.35) 로 맞는다.

## 2. 표적 (7) 규약 판단 — 왜 179 를 C17200 으로 봤나
BRIEF_DRAFT 의 해당 절에 근거 넷을 적었다. 핵심은 **셈**이다 — 179 의 출처 일곱이 전부 C17200 문서이고
경쟁 등급 문서가 0건이며, 導電率 22 %IACS 라는 구별 열이 C17410/C17510(45~60 %IACS)을 배제한다.
`material.name` 은 병합기 자연키라 **바꾸지 않았고**, 판정을 전파되는 `verdict_` 접두어에 박았다.

## 3. 사고 — `apply_core_verdicts.py` 가 하드코딩 경로로 라이브를 쳤다
사본 리허설 중에 판정만 라이브에 들어갔다. `_before_correction` 이 옛 값을 보존하고 적용 내용이
원래 라이브에 넣을 것이었으므로 피해는 없다. 값 적재를 곧바로 라이브에 이어 적용해 상태를 맞췄다.
**고칠 자리는 그 스크립트의 `DB` 상수**이고, 채굴 배치는 공유 도구를 안 고치므로 신고만 한다(§468).

## 4. 신고(고치지 않았다)
- **TOKKIN C5210 제품페이지의 융점 `871-982 ℃` 는 C1720(CuBe)의 값으로 보인다** — 같은 벤더의
  C1720 페이지가 글자까지 같은 문자열을 찍고, 871/982 ℃ = 1600/1800 °F 이며 CDA C52100 은
  1620/1880 °F 다. 옆에 데이터북의 고상선 880 / 액상선 1020 을 세우고 그 행 notes 에 적었다.
- **재료 179 의 tier 둘이 규약과 어긋난다** — CDA 피로 3행(t3, 사유 무효) · MakeItFrom 5행(t2인데 집계 사이트).
  `verdict_tier_convention` 에 이름으로 적었다.
- **JCBA 표 1.2 의 `ばね限界値`·`たわみ係数` 열은 아직 아무도 안 넣었다**(ZB 도 안 넣었다).
  카탈로그에 대응 키가 없다 — 갈래를 새로 여는 것은 §636 이 막으므로 신고만 한다.
