## 1. 문제 정의 — 왜 물성 카탈로그인가

### 1.1 해석이 도는 것과 안 도는 것

해석 하나를 돌리려면 그 해석이 요구하는 물성이 **전부** 있어야 한다.
아홉 개가 있고 하나가 없으면 결과는 90%가 아니라 **0%**다. 덱이 안 만들어진다.

이 성질이 이 프로젝트의 모든 판단을 지배한다.

- 물성값 총량을 늘리는 것과 해석 가능한 재료를 늘리는 것은 **다른 일**이다.
- 그래서 "물성값 41,396건"은 성과 지표가 아니다. **재료마다 마지막 한 칸이 다르면
  총량이 아무리 늘어도 돌아가는 해석은 늘지 않는다.**
- 8차 파동에서 방침이 한 번 크게 바뀐 이유도 이것이다 —
  **덱이 도는 것과 안 도는 것의 차이가, 그 값이 tier1이냐 tier3이냐의 차이보다 크다.**

### 1.2 격자 — 무엇을 세고 있나

카탈로그의 재료는 **2,654종**이다. 그러나 이 전부를 격자에 넣지 않는다.
`attributes.role`이 세 값으로 갈린다.

| role | 종수 | 무엇인가 | 격자 |
|---|---:|---|---|
| `product` | **864** | 스마트폰 부품으로 실재하는 제품·등급 | **센다** |
| `evidence` | 1,723 | 논문의 연구용 조성(`PC/ASA/PMMA blend 1 black 2`) — 계열 근거로만 쓴다 | 뺀다 |
| `out_of_scope` | 67 | 실재 상용 제품이나 다른 도메인(교정용 아치와이어·콘택트렌즈·변압기 절연지) | 뺀다 |

**격자 밖 재료의 값은 그대로 남는다.** 뺀 것은 분모이지 데이터가 아니다.
그리고 이 구분은 구조적 부재와 다르다 — 부재는 "그 물성이 없다"이고 이건 "그 해석의 대상이 아니다".

그리고 이 864종에도 물성 정의 264종을 다 곱하지 않는다.
알루미나에 투습도를 요구하거나 벌크 금속에 층두께를 요구하면 **없는 결함을 만들어내는
지표**가 된다(실제로 그렇게 세다가 벤딩을 8%, 결로를 4%로 잘못 셌다 — 21장).

### 1.3 분모가 커졌다 — 채움률이 떨어져 **보이는** 이유

13차 파동 마감(2026-08-10)의 격자는 **재료 544종 · 14,478칸**이었고 셀 채움 97.4%였다.
지금은 **864종 · 23,127칸 · 66.4%**다.

**값을 잃은 것이 아니다.** 물성값은 21,279 → 41,396건으로 **1.95배**가 됐다.
같은 기간에 격자가 1.60배가 됐고, 새로 들어온 재료가 **빈 채로 분모에 먼저 앉았다.**

| | 13차(2026-08-10) | 54차(2026-09-01) | 배율 |
|---|---:|---:|---:|
| 물성값 | 21,279 | **41,396** | 1.95 |
| 격자 대상 재료 | 544 | **864** | 1.59 |
| 격자 칸 | 14,478 | **23,127** | 1.60 |
| 채워진 칸 | 14,102 | **15,358** | 1.09 |
| 셀 채움 | 97.4% | **66.4%** | — |

**13차판 §5.2가 그것을 예고해 놓고 41개 파동 동안 갱신되지 않았다**(§16.12).
13차판 §5.2는 *"칸/재료가 1.00으로 평평해졌다 … 기본 물성이 닫히면 이 척도는 스스로 수명을 다한다"*고
적었다. 척도가 수명을 다한 방식이 예고와 달랐을 뿐이다 —
레버리지가 평평해져서가 아니라 **분모가 세 번 커져서**다(16차 544→731 · 이후 864).

**그래서 "채움률이 떨어졌다"는 문장은 이 카탈로그에서 성립하지 않는다.**
같은 격자에서 재야 비교가 된다. 지금 비교 가능한 것은 **칸의 절대 수**뿐이고
그건 14,102 → 15,358로 늘었다.

## 2. tier 체계 — 등급이 무엇을 뜻하고 왜 tier4를 허용하는가

### 2.1 네 등급

tier의 기준은 **"문서의 종류"가 아니라 "값의 성격"**이다. 벤더 TDS든 논문이든 상관없다.

| tier | 뜻 | 건수 | 비율 |
|---|---|---:|---:|
| **1** | 그 제품·시편에 대해 **문서에 인쇄된 실제 시험값**(벤더 TDS·그 재료를 시험한 논문) | 25,414 | 61.4% |
| **2** | 핸드북·표준 최소보증치·공인 DB(MMPDS·ASM·NIST·CDA·ISO/ASTM) | 3,554 | 8.6% |
| **3** | 계열·클래스 대표값 / 2차 인용 / 등급 불일치 대체값 | 7,932 | 19.2% |
| **4** | 계산·유도·추정·가정 | 4,496 | 10.9% |
| | **합계** | **41,396** | |

**tier1 비율이 44.8%에서 61.4%로 올랐다.** 16차 이후 파동이 벤더 시트를 직접 여는 쪽으로
표적을 바꾼 결과다(브리프 §127 — *"시트를 실제로 열어 확인했다"*). 같은 이유로 tier3이
26.4%에서 19.2%로 줄었다 — **계열 대입으로 닫았던 칸이 그 제품 자신의 인쇄값으로 갈아 끼워졌다**(§14.1).

`method`는 **measured / handbook / computed / estimated / digitized** 다섯을 쓴다.
`datasheet`는 방법이 아니라 출처 종류다(한때 method로 쓰여 902건이 섞여 있었다).

**`digitized`는 40차에 새로 열었다** — 그림에서 읽은 값이다(브리프 §447·448).
이걸 `measured`로 넣으면 **인쇄 실측과 구별이 안 된다.** 현재 826건이고, 규칙 3(§3)의
예외 경로를 통과한 값만 여기 들어온다.

| method | 건수 |
|---|---:|
| measured | 28,815 |
| estimated | 4,409 |
| computed | 3,733 |
| handbook | 3,613 |
| digitized | 826 |

### 2.2 tier4를 허용하되 반드시 표시하는 이유

7차까지는 "빈 칸이 틀린 값보다 낫다"를 가장 강하게 해석했다.
8차에서 방침이 바뀌었다 — **계열 대표값(tier3)과 근거 있는 가정(tier4)까지 허용해
일단 칸을 닫는다.** 다만 바뀐 것은 **어느 tier까지 허용하느냐**이지
**근거 없이 지어내도 되느냐**가 아니다.

그래서 tier4에는 **두 개의 구조적 표지**를 필수로 박는다.

```json
"conditions": { "assumption": true },
"method": "estimated"
```

이 두 줄이 하는 일은 셋이다.

| 장치 | 어디서 작동하나 | 효과 |
|---|---|---|
| 대표값 선택(`_rep_rank`) | 조회·비교·DYNA 카드 | tier가 낮은 값이 이긴다 → 가정값은 **항상 실측에 밀린다** |
| UI 배지(`tierBadge()`) | 화면 | tier4 + `assumption`이면 "계산/등가"가 아니라 **"가정"**(danger 색)으로 표시 |
| 무결성 검사 2항목 | 배포 전 | `가정값인데 tier4·estimated 아님` · `가정값인데 근거 출처 없음` |

**핵심은 자동 대체다.** 나중에 실측이 들어오면 그 순간 대표값이 바뀐다 —
사람이 손으로 지울 필요가 없다.

**실제로 작동한 것을 확인한 사례가 있다.**

- 배터리 분리막 포아송비가 **tier4 추정 0.4 → tier2 실측 0.17**로 대표값이 갈아 끼워졌다(47장).
  가정값을 넣을 때 설계한 대로 동작했다.
- Al7050-T7451의 피로계수가 **tier4 추정(Meggiolaro-Castro 1.9×Su = 996 MPa) →
  tier3 실측 계열대체(AA7075-T6 FD&E 피팅 876 MPa)**로 올라갔다(FDE_FATIGUE_ARCHIVE).

### 2.3 그리고 반대 방향의 함정

가정값이 정직하게 새겨져 있어도 **가정 위에 가정을 쌓으면** 소용없다.
포아송비 가정값을 만들 때 처음엔 전체 값으로 클래스 중앙값을 냈는데,
폼 4건이 전부 0.300이고 편차가 0이라 이상해서 보니 **이미 tier4 가정값**이었다(33장).
근거를 tier1·2로 한정해 다시 계산했다.

**앵커로 쓸 행은 값과 tier만 보면 안 된다. `method`와 `notes`를 반드시 읽어야 한다.**
8차 파동이 VHB 계열 13종에 0.894 MPa를 옮기면서 근거를 "Satas 핸드북 계열값"이라 적었는데
실제 정체는 같은 재료의 G와 ν로 만든 **역산값**이었다(71장).

## 3. 절대 넘지 않는 선 — 그리고 그 규칙이 막아 온 사고

규칙은 추상이 아니다. **전부 실제로 사고가 나서 생겼다.**

### 규칙 1 — 지어내지 않는다. 빈 칸이 틀린 값보다 낫다.

문서에 실제로 인쇄된 숫자만 넣는다.

- **라미네이트 밀도 16종을 비워 뒀다.** Isola 370HR SDS가
  `SPECIFIC GRAVITY: Not Available for product`라고 **명기**한다. 유사 제품 값(RF-35TC 2.35 등)을
  규칙대로 대입하지 않았다 — **이 칸은 비어 있는 게 정답이다.**
- **Kaneka Graphinity의 1200 W/mK를 채택하지 않았다.** 무역기사에만 뜨는 숫자이고
  데이터시트도 논문도 아니다. 제품 페이지는 404이고 Wayback 스냅샷도 없다.
- **8차 파동은 항복강도 258종 중 69종만 닫았고 그게 정답이었다.** 171종은 항복강도가
  **물리적으로 존재하지 않는다** — 세라믹·유리는 취성 파괴(49종), 고무는 초탄성(64종),
  저분자 유기 고체는 벌크 소성 시험이 성립하지 않는다(55종).

### 규칙 2 — 역산 금지. 다른 물성에서 계산한 값을 저장하지 않는다.

가정과 역산은 다르다. **가정은 "이 계열은 대개 이 값이다"이고, 역산은 "다른 물성에서 계산했다"이다.**

| 사고 | 실체 | 피해 |
|---|---|---|
| VHB 영률 0.894 MPa (71장) | `E = 2G(1+ν)` 역산값인데 notes에는 "Satas 핸드북 계열값" | **역산값 하나가 13종으로 번지고 근거 표기까지 틀린 채로 남았다.** 14행을 되돌렸다 |
| AZoM/Granta의 폴리머 `Shear Modulus` (69장) | PU·PET·PP·PI·에폭시 5계열에서 `E/(2(1+ν))`와 **유효숫자까지 일치** | 폴더블 벤딩 G 칸을 채워주는 최대 출처가 통째로 쓸 수 없는 값이었다 |
| MakeItFrom의 폴리머 G (69장) | LDPE가 E=0.30 GPa·G=0.21 GPa를 동시에 인쇄 → **ν=−0.29** | 같은 사이트의 **금속**은 정합한다. 폴리머만 오염 |
| Nitto 5000 박리강도 12.5 MPa (69장) | 원문 "20 N/cm"(폭당 힘)를 누군가 두께로 나눔. **tier1 실측으로 들어가 있었다** | 테이프는 점착층+캐리어 적층이라 전체 두께로 나눈 값은 **어느 층의 강도도 아니다** |
| Panasonic PGS·Kaneka 흑연시트 (72장) | 도전율(S/cm)만 인쇄된 것을 역수 취해 저항률로 넣으려 함 | 3종을 비웠다 |

**단, 9차 파동에서 한 칸을 열었다(0-B절).**
**문헌이 "실측이 없을 때 이렇게 추정하라"고 공표한 상관식은 쓴다** —
Universal Slopes(Manson 1965), Modified Universal Slopes(1988), Roessle-Fatemi(2000),
Meggiolaro-Castro Medians(2004), Gent(1958). 출처는 **그 추정식 논문**이고 입력값과 식을
notes에 전부 적는다.

**둘의 차이는 누가 그 관계를 보증하느냐다.** 공표된 상관식은 저자가 적용 범위와 오차까지
밝히고, 손으로 세운 항등식은 아무도 보증하지 않는다.

### 규칙 3 — 그래프에서 값을 읽지 않는다. 읽었으면 `digitized`로 표시한다.

- **아크릴 PSA 열전도율 앵커 0.176 W/(m·K)** — notes는 "0 wt% 대조군 실측"이라 적혀 있었으나
  **인용 논문 전문에 `0.176`은 0회 등장한다.** 논문이 인쇄한 것은 충전계 0.8347과 0.9552뿐이고
  순수 PSA 값은 Figure에만 있다. 3M 467MP TDS 인쇄값 0.158로 교체했다(71장).
- **SUS430 율속 데이터 전량 폐기** — 원문 터키어가 "그림 4에서 읽었다"였다(69장).
- **예외 하나** — `pdftotext`가 조용히 빈 표를 주면 그 표는 **이미지**다.
  `pdftoppm -png`로 렌더해 읽는 것은 **그래프가 아니라 표이므로 규칙 3에 걸리지 않는다.**
  이 단계가 없었으면 7차 파동이 표 전체를 "없다"고 결론지었다.

**39~41차에 이 규칙의 경계가 다시 그어졌다.** 규칙 3이 막으려던 것은 "그림에서 읽었다는
사실이 감춰지는 것"이지 그림 자체가 아니었다. 그래서 **읽되 표시하는 경로**를 열었다(브리프 §447·448).

| 지켜야 할 것 | 왜 |
|---|---|
| `method: "digitized"` | `measured`로 들어가면 **인쇄 실측과 구별이 안 된다.** 로더 어휘라 `"digitized"` 그대로 써야 한다 |
| 벡터 좌표를 읽어라 | 픽셀 추적이 아니다(§452). `pdftocairo`가 마커를 `M … Z M <꼭짓점>`으로 내보내 **한 꼭짓점을 더 찍는다** — 안 지우고 평균하면 삼각형 마커 중심이 `±h/6` 밀린다(§514·541) |
| 이중축은 검산이 아니다 | `ksi/MPa` 두 라벨이 **같은 눈금선에 앉아 있다.** 왕복검산이 성립하지 않는다(§445·449) |
| 눈금선은 균일하지 않다 | 벤더 차트에 전역 선형 보정을 걸면 값이 1.5% 흔들린다(§446) |
| 인계받은 그림 번호는 검증 대상이다 | 47차 IB가 앞 배치의 "Fig.14"를 다시 열어 계통오차를 확인했다(§496·524) |

**그리고 그림은 그림끼리도 어긋난다.** 한 논문의 두 그림에서 곡선 극대점이
저자 인쇄값보다 17% 높았고(§494), 다른 저자는 **그림을 통째로 복제하고 라벨만 바꿨다**(§493).

### 규칙 4 — 재인쇄본·2차 인용을 믿지 않는다.

"[12]에 따르면"으로 시작하는 표는 1차 출처까지 따라간다. 못 가면 tier3으로 낮추고 notes에 적는다.

- **Polymers 12(10) 2327 Table 4에서 온 19건** — 캡션이 `[48,56-67]`로 2차 인용을 밝히고,
  같은 표의 PC 밀도 1.44·PE 1.38이 실제값(1.20·0.92)과 어긋난다. 지우지 않고
  **각 행에 검산 실패를 박았다**(69장).
- **Kwatra Table 2.1이 Ferguson 값을 8.18로 오기** — 원문은 8.48이다. 2차 블록을 폐기하고
  1차로 교체(51장).
- **복사 계보** — PV 적층 물성표(EVA 2090, Tedlar 1250)가 arXiv·Buildings·PMC
  **세 문헌에 바이트 단위로 복사**돼 있었다. **같은 숫자 조합이 여러 논문에 나오면
  독립 확인이 아니라 한 출처의 재인쇄다.** 한 건을 검산해 버리면 나머지도 같이 버린다(71장).

### 규칙 5 — 조건 없는 값은 값이 아니다.

온도·주파수·방향·습도·하중비·파장은 그 물성의 **정의 조건**이다.

- **3M VHB 4910 TDS의 `Shear Modulus 6 × 10⁵ Pa`** — 시험규격도 변형률속도도 없다.
  같은 재료의 율속 분해 문헌값(평형 1.726e4 / 순간 4.876e4 Pa)보다 12~35배 크다.
  tier1로 두면 **조건 없는 값이 대표로 뽑혀 조건 붙은 값을 밀어낸다.** tier3으로 내렸다(24장).
- **파장 없는 굴절률·반사율 75건** — 파장이 없으면 값 자체가 해석 불가다.
  실리콘 소광계수는 400 nm에서 0.387, 1000 nm에서 0.0005로 **800배** 차이난다.
  tier4로 내려 대표값에서 빠지게 했다(지우지는 않았다).
- **필수 조건 목록** — 열전도율·CTE·유전율은 온도, 복합재·박막은 방향 / 유전율·손실계수는
  주파수 / WVTR은 온도·RH·두께 / 접촉각은 액체 종류와 전진·후퇴·정적 / 박리강도는
  각도·피착재·속도.

**충돌은 값의 문제가 아니라 조건이 덜 적힌 문제인 경우가 많다.**
인제스터가 "조건이 같아 뒤엣것이 앞엣것을 덮는다"고 5건을 거부한 적이 있는데, 뜯어보니
Nitinol은 **초탄성이라 항복점이 둘**(상변태 개시 / 전위 소성)이었고 Al6063은
**같은 공칭 율속의 다른 시편**이었다. `yield_definition`·`specimen`을 조건에 넣자
76건 전부 들어갔다(69장).

### 규칙 6 — 그 재료의 상위 tier 값과 자릿수가 어긋나면 넣지 않는다.

**등급 불일치는 tier를 낮춰 쓸 수 있지만, 같은 재료의 tier1 실측과 직접 모순되는 값은 다르다.**

후자는 **카드를 물리적으로 앞뒤 안 맞게 만든다.**

## 4. 파동(wave) 사이클 — 한 바퀴에 무엇을 하고 무엇을 검사하나

한 파동은 대략 **하루~이틀**, 병렬 배치 **6~11갈래**다. 순서는 고정이다.

| # | 단계 | 하는 일 | **무엇을 검사하나** | 도구 |
|---|---|---|---|---|
| 1 | 빈칸 분석 | 격자에서 비어 있는 칸을 뽑는다 | 구조적 부재를 뺀 **채울 수 있는 칸**인가 | `coverage_report.py` |
| 2 | 표적 선정 | 어느 계통의 어느 빈칸을 캐나 | **계통으로 자르고 갈래로 갈라라**(§5·§6·§7) | `coverage_report.py` · `attributes` |
| 3 | 타깃 파일 생성 | 배치별 재료 목록 | **무엇이 없어서 이 재료가 뽑혔는지를 함께 적는다** | — |
| 4 | 병렬 배치 투입 | 브리프 + 타깃 파일을 각 배치에 | 배치마다 `scratchpad/<영역>/` 분리 | `COLLECTION_BRIEF.md` |
| 5 | chunk 중간 저장 | 재료 10~12종마다 파일을 쓴다 | 프로세스가 죽어도 남는가 | — |
| 6 | JSON 파싱 검증 | `json.load()` | 파싱 실패 0 | — |
| 7 | 인제스트 드라이런 | `ingest_agent_json.py <dir>` | **6단계 검증**(아래) | 인제스터 |
| 8 | 적용 | `--apply` | 신규 재료·거부 사유 리뷰 | 인제스터 |
| 9 | tier 정규화 | 값의 성격으로 등급 재판정 | 자동 규칙 vs `MANUAL`/`FROZEN` 예외 | `normalize_tiers.py` |
| 10 | 무결성 검사 | 50항목 + 주의 6갈래 | **0이 아니면 결함** | `integrity_check.py` |
| 11 | **운영 전파 예행** | 적재 직전 백업 대 적용 후로 병합을 돌린다 | **`added 0` · `*_misses 0`**(§11.3) | `_materialtwin_merge.py` |
| 12 | 통계·문서 재생성 | 커버리지·xlsx·docx | 하드코딩 없이 전부 계산값인가 | `build_*` 스크립트 |
| 13 | 이력 기록 → 배포 | 무엇이 틀렸는지까지 | — | `COLLECTION_BRIEF_CORPUS.md` |

**11단계가 43차에 새로 생겼다.** 그 전까지 파동은 "dev에서 고쳤다"로 끝났고,
**고친 것의 상당수가 운영에 한 건도 안 갔다**(§9의 ⑦). 지금은 그것이 합격 조건이다.

**그리고 커밋은 경로를 제한한다.** 병렬 배치가 git 인덱스를 공유해서
`git commit`이 남의 스테이징을 삼킨 사고가 **네 번** 났다(§504·530·542·553).
네 번째는 경로 제한으로도 못 막았다 — **같은 파일을 두 배치가 만졌기 때문**이다.
검출기는 `git show --stat`의 **"삭제 줄수 0"**이다.

### 4.1 5단계가 왜 규칙이 됐나

8차 파동 첫 투입분 6개가 결과를 **마지막에 한 번만** 쓰도록 돼 있었고,
프로세스 종료로 **산출물이 0**이었다. 여섯 배치가 통째로 날아갔다.
재투입할 때 chunk 저장을 강제했고 이후 중단 없이 회수됐다.
**장시간 배치는 중간 저장을 설계에 넣어야 한다.**

같은 종류로, 7차 파동은 세션 한도로 끊겼는데 **끊긴 배치가 이미 해놓은 일이 기록되지
못했다** — 다음 세션의 피로 배치가 MIL-HDBK-5H를 찾으러 갔더니 앞 세션이 이미 2.28 MB를
받아 스크래치패드에 두었다. **중단된 파동의 스크래치패드를 먼저 뒤져야 한다.**

### 4.2 7단계 — 인제스트가 거부하는 것

**에이전트는 DB에 직접 쓰지 않는다.** SQLite 락 경합을 피하고 등록 전 검토 지점을 만들기
위해 JSON으로 내놓게 하고, 메인이 검증 후 직렬 등록한다.

| # | 검증 | 무엇을 막나 |
|---|---|---|
| ① | `property_key`가 taxonomy에 있는가 | 그럴싸하지만 없는 키를 지어내는 것(`poissons_ratio`, `expansion_coefficient`…) |
| ② | 단위가 정의 단위와 일치하는가 | 곱 순서만 다른 표기(`m²·K/W` vs `K·m²/W`)는 같게 보되 기호가 다르면 거부 |
| ③ | 출처(url/doi/title)가 있는가 | **없으면 항목 전체 건너뜀.** 스키마 설계 때부터 강제라 "출처 없음"이 끝까지 0 |
| ④ | 물리적 범위 안인가 | 40여 키에 범위. **신규 키는 범위 자체가 단위 검산**이다(CS를 MPa 원값으로, DOL을 µm 원값으로 넣으면 걸린다) |
| ⑤ | 비율 물성이 1을 넘지 않는가 | 연신율·흡습률 퍼센트 오입력(100배 오류) |
| ⑥ | 기존 tier1 실측을 덮지 않는가 | **단, 조건이 다르면 별개 측정이므로 통과** |
| + | 조건 충돌 | 조건 서명이 같은데 값이 다르면 **덮어쓰기 대신 거부**하고 사유 보고 |

⑥의 단서가 왜 붙었는지 —
처음엔 "기존 tier1을 덮지 않는다"가 **조건이 다른 별개 측정까지 막았다.**
그리고 반대로, 적재가 (재료·물성·출처·조건)에 멱등이라
**조건이 같고 값만 다르면 나중 것이 앞의 것을 조용히 덮는다.**
3M Viscoelastic 112P05 박리력이 112P02와 시험조건이 같아 이렇게 사라져 있었다 —
그레이드가 `conditions`가 아니라 `note`에만 있었기 때문이다.

### 4.3 10단계 — 무결성 검사 50항목

배포 전 반드시 0으로 통과시킨다. 현재 **50항목 중 49항목이 0**이고,
남은 하나는 `물성값 0인 재료 2`다 — 등록·삭제 시험이 남긴 `업로드시험강`·`삭제확인강`이다.
(재료 2290은 세트가 통째로 이동해 값이 0이지만 **묘비**(`merge_verdict: moved`)를 세워서
이 검사에서 빠진다 — §11.5.)

| 검사군 | 항목 예 |
|---|---|
| 참조 무결성 | 출처 없는 값 · 끊어진 출처 참조 · 정의 없는 물성키 · 고아 시편 |

| 표시 규율(신규) | **묘비 선언이 깨졌다** · 묘비가 옮겼다는 키가 대상에 없다 · 중앙값인데 실측·핸드북 표기 |

**주의는 여섯 갈래이고 지금 넷이 켜져 있다.** 결함으로 세지 않고 경고로 남긴다.

**마지막 항목이 중요하다.** 방향을 지어내서 검사를 통과시키는 것도, 아는 위험을 안 알리는
것도 안 된다. 그래서 결함으로 세지 않고 **경고로 남긴다.**

**그리고 검사기는 DB 경로를 박으면 안 된다.** 53차 OB가 적용 전 백업과 적용 후 라이브로
각각 돌려 diff를 떴는데 **두 출력이 글자까지 같았다** — 환경변수를 무시하고 둘 다 라이브를
쳤기 때문이다. 하마터면 "내가 깬 것이 없다"로 넘어갈 뻔했다.
**검사기가 스냅샷을 못 치면 배치는 자기가 무엇을 깼는지 모른다**(§572).

## 5. 계통(subsystem) 축 — 스마트폰 부품 기준으로 세는 법

**43·49차에 태깅이 끝나 이제 격자를 계통으로 자를 수 있다.**
그 전까지 이 카탈로그는 "폴리머 몇 종·금속 몇 종"으로만 셀 수 있었다.
그건 재료과학의 축이지 **제품의 축이 아니다.**

### 5.1 지금 계통이 어떻게 서 있나

`role=product` 864종 중 **779종에 계통이 붙었고 85종은 "붙일 수 없다"가 판정으로 붙었다**
(`verdict_subsystem` + `subsystem_basis`). 미판정은 0이다.

핵심 물성 일곱(밀도 · E · ν · 비열 · 열전도율 · CTE · UTS)의 채움률을 계통으로 자르면 이렇다.

|---|---:|---:|---:|
| coating | 7 | 100.0% | 0 |
| rf | 24 | 95.8% | 7 |
| emi | 3 | 95.2% | 1 |
| passive | 11 | 90.9% | 7 |
| wlp | 11 | 87.0% | 10 |
| housing | 160 | 86.8% | 148 |
| sensor | 5 | 80.0% | 7 |
| acoustics | 15 | 79.0% | 22 |
| camera | 41 | 74.9% | 72 |
| semiconductor | 13 | 70.3% | 27 |
| pcb | 178 | 69.2% | 384 |
| display | 79 | 67.1% | 182 |
| thermal | 42 | 62.6% | 110 |
| (계통 판정만 있고 값 없음) | 85 | 57.1% | 255 |
| battery | 36 | 51.6% | 122 |

| **전체** | **864** | **67.4%** | **1,973** |

### 5.2 어휘가 같은 모듈의 부품을 가른다 — 값이 아니라 어휘를 검산해라

43차 EA가 태그를 붙이며 어휘 자체의 결함 셋을 찾았다. **전부 같은 지문이다 —
한 모듈의 부품이 서로 다른 계통값에 들어가 있었다.**

```
보이스코일선  = audio     ↔  진동판 필름 = speaker    (같은 스피커 모듈)
압연동박      = pcb       ↔  압연동박    = fpcb       (같은 것이 둘)
TSV 구리      = packaging ↔  TSV 배리어  = soc        (같은 공정 재료)
```

그리고 `soc` 10종에 SoC가 **하나도 없었다.** 전부 RDL 유전체·Cu 필러·TSV 배리어다 —
**이름이 내용과 다르면 화면에서 못 찾는다.**

- 갈린 값은 필터를 쓸모없게 만든다. "스피커 재료"를 눌러도 진동판만 나오고 코일선은 빠진다.
- **찾는 법** — 어휘값마다 재료를 나열하고 *"이 중 둘이 같은 부품의 짝인가"*를 물어라.
  종수가 1~2인 값은 특히 의심하라(`fpcb`는 고아 하나였다).
- **합치는 이름은 가장 넓은 것을 골라라.** `acoustics`만이 메시·펠트·진동판·코일선을 다 담는다.

**그리고 어휘를 합치면 지시문도 고쳐야 한다**(§466). 465번을 적용한 직후 **옛 값이 8종
되살아났다** — 같은 파동의 배치 지시문에 `subsystem="speaker"`가 적혀 있었고 그 배치가
아직 돌고 있었기 때문이다.

**일반화 — 어휘·키·등급을 합칠 때는 세 곳을 같이 봐라.**
**① 이미 든 데이터 ② 아직 들어올 데이터(도는 배치·지시문) ③ 그 값을 읽는 코드.**
하나라도 빠지면 되살아난다.

### 5.3 화면으로 조사하면 화면이 거른 것은 안 보인다

이것이 계통 축을 세우면서 얻은 가장 비싼 교훈이다(§528).

| 인계(45·46차) | 실측(전수 조사) | 배율 |
|---|---|---:|
| OLED 소분자 **8종** + fac-Ir(ppy)₃ **1종** | 분자·유기금속 **172종** | **19배** |
| 순수 탄소 분말·섬유 **7종** | 원소 탄소 **24종** | 3.4배 |
| GST 4종 · MLCC 칩 1종 | **0종**(결함이 아니었다) | — |

**왜 이렇게 벌어졌나** — 인계는 *브리핑한 사람이 화면에서 본 재료*를 센 것이다.
OLED 소분자는 `subsystem='display'`인 8종만 눈에 띄었고, **나머지 164종은
`subsystem`이 비어 있고 `role='evidence'`라 어느 화면에도 안 뜬다.**
(지금 `category='molecular'`는 **172종**이다 — 그 조사가 옮긴 수와 같다.)

**전수 조사의 지문 두 개를 합집합으로 써라 — 어느 하나도 혼자서는 못 잡는다.**

- **물성키 지문** — 분자궤도·발광 키(`homo_level`·`lumo_level`·`triplet_energy_t1`·
  `singlet_energy_s1`·`photoluminescence_quantum_yield`·`emission_peak_wavelength`)를
  가진 재료는 "분자로 특성화됐다"는 **구조적 증거**다. 166종을 잡는다.
  그런데 발광 고분자와 무기 나노결정(양자점 5종)도 같이 걸린다.
- **이름 지문** — 물성키가 `optical` 하나뿐인 23종을 잡는다. 대신 오탐이 있다
  (`Fe-18Cr-12Mn-N austenitic steel`이 걸렸다).

→ **합집합으로 넓히고 제외 지문으로 깎아라.** 최종 172종.

**탄소만은 이름 목록으로 갔다.** 정규식으로 쓸면 `Epoxy + Graphite 40 wt%` 같은
**진짜 복합재를 죽인다.** 탄소 토큰 보유 208종을 전수로 눈에 넣고 24종을 골랐다.

**규율 — 계통·역할처럼 화면이 거르는 축에서는 "화면에서 본 수"를 인계로 받지 마라.
DB 지문으로 다시 세라.**

## 6. 빈칸의 네 갈래 분해 — "더 캐면 된다"가 아니다

**이 장이 53·54차의 결론이다.** 채움률이 낮은 칸을 표적으로 삼기 전에
그 빈칸을 네 갈래로 갈라야 한다.

| 갈래 | 뜻 | 표적인가 |
|---|---|---|
| **① 등급 미확정** | 벤더·등급이 아니라 클래스 서술이다(`Conventional FR-4`, 익명 코드) | **원리적으로 못 닫는다** |
| **② 해당 없음** | 그 재료에 그 물성이 성립하지 않는다(OSP 표면처리의 인장강도 — 0.2~0.5 µm 유기 전환피막이라 자립 시편이 없다) | 아니다 |
| **③ 벤더 구조적 부재** | **시트를 실제로 열어** 그 칸이 없음을 확인했다 | 아니다(위탁시험뿐) |
| **④ 진짜 남은 것** | 캘 수 있다 | **여기만 표적이다** |

**그리고 ③을 "아직 아무도 안 열어 본 것"과 섞지 마라.** 셋 다 "값이 없다"지만
③만 근거가 있다. 미확인은 별도 갈래로 세고, **다음 배치의 표적은 거기**다.

### 6.1 실례 둘 — 444칸과 391칸

**(가) packaging 빈칸 444개**(53차 OC · §582)

- **17종 92칸은 등급 미확정**이라 원리적으로 못 닫는다(익명 코드·클래스명만 인쇄).
- **솔더 페이스트 3종 21칸은 0/7이 정상**이다 — 코어는 분말 합금의 것이다.
- **최대 결손인 포아송비 83칸·비열 74칸은 벤더가 구조적으로 안 찍는다** —
  이번에 연 시트 **7장 중 포아송비를 찍은 것이 0장**, 비열은 하나뿐이다.
- EMC는 51개 등급이 `grade` 조건으로 이미 전량 들어가 있어 코어가 닫혀 있다.

**(나) pcb 빈칸 391개**(54차 PC · §584) — 채움률 68.6%가 "31%를 더 캘 수 있다"는 뜻이 아니었다.

| 계열 | 빈칸 | 재료 | 무엇인가 |
|---|---:|---:|---|
| ① 등급 미확정 | 12 | 2 | Ehrler 2002의 `Conventional FR-4`·`FR-4-180` — 클래스 서술이다 |
| ② 해당 없음 | 1 | 1 | OSP 표면처리의 인장강도 |
| **③ 벤더 구조적 부재** | **271** | **83** | 벤더 문서 9종을 **실제로 열어** 대조했다 |
| ③b 제품페이지 단독 | 41 | 15 | 전제품 TDS에 **행 자체가 없는** 등급이다 — 확인 못 한다 |
| ③c 논문 미인쇄 | 28 | 5 | 그 논문은 박리·Tg·z팽창·CTEz·Dk·Df만 잰다 |
| 재료 중복 | 12 | 2 | 같은 제품이 카탈로그에 이미 서 있다 |
| **④ 진짜 남은 것** | **7** | **5** | 캤다 |
| 미확인 | 19 | 9 | 시트를 안 열었다 — **다음 표적은 여기** |

**391 중 캘 수 있었던 것은 7칸이다.**
그리고 ③의 근거는 계통적이다 — IPC-4101 계열 적층판 데이터시트는 비열·ν·UTS 같은
코어 다섯을 **구조적으로 안 찍는다**(§585).

### 6.2 채움률이 가장 낮은 계통이 표적이 아닐 수 있다

54차 PC가 계통을 고르려고 전수로 쟀더니 **가장 낮은 곳은 조정자 목록에 없던 magnetics(35.9%)**였다.
그런데 열어 보니 빈칸 175개는 전부 하드페라이트 25등급이 코어 7칸을 통째로 비운 것이고,
그 재료를 만든 배치가 이미 판정을 적어 두었다 —

> Eclipse 문서의 `Physical Characteristics (Typical)` 표는 **등급별이 아니라
> 소결 하드페라이트 공통값**이라 여기 25등급에 복제하지 않았다 —
> 한 값을 25번 복제하면 커버리지가 부풀고 계보가 흐려진다.

**즉 175칸은 미채굴이 아니라 이미 내려진 판정이다. 채굴 잔여는 0이다.**

- **낮은 채움률은 표적 신호가 아니다.** 고르기 전에 그 계통 재료의 `attributes`를 읽어라 —
  앞 배치가 왜 안 넣었는지 거기 적혀 있을 수 있다.
- **판정을 남길 때는 그 판정을 읽을 코드가 보는 자리에 남겨라**(§593).
  magnetics의 판정은 자유 키 `grade_table_scope`에 있어 **집계가 못 읽었다.**
  §582가 정한 자리는 `core_not_applicable`이고, 54차 PC는 70종에
  `core_absent_from_vendor_sheet`를 달았다. **자유 키에 있으면 다음 파동이 같은 175칸을 또 센다.**

### 6.3 키 부재는 값 하나가 아니라 갈래 전체를 막는다

43차 ED가 자성재를 캐고 보고했다 — *"(BH)max 키 하나 때문에 NdFeB 8등급 × min/typ과
페라이트 20여 등급이 통째로 못 들어갔다. 값은 이미 손에 있다."*

**키 부재를 "값 하나 못 넣음"으로 세면 우선순위가 틀린다.**
자성재 카탈로그는 등급표라 **한 키가 열리면 표 전체가 한꺼번에 닫힌다.**
반대로 그 키가 없으면 등급을 아무리 캐도 반쪽이다.
43차 EE가 `magnetic.energy_product_max`를 열었고 지금 그 키에 **80행·38종**이 서 있다.

- 배치는 **막힌 값의 수를 세어 보고해라** — "키 없음"이 아니라 "이 키가 없어 N행이 막혔다".
- **키 신설은 채굴과 분리된 배치로 돌려라.** 채굴 배치가 키를 만들면
  파동마다 어휘가 늘고 서로 충돌한다(§419).
- **키를 열 때는 짝이 되는 칸까지 같이 넣어야 검산이 닫힌다**(§470).
  (BH)max만 넣고 Br을 안 넣으면 `(BH)max ≤ Br²/(4µ₀)`를 걸 수가 없다.
- **키를 가를지 말지는 차원이 정한다**(§453). 물리적 의미가 아니다.
  다만 **차원이 같아도 하중방식이 다르면 가른다**(§508).
- **"1행짜리 키"인지는 DB가 정한다.** 인계 1행이 실제로는 6행이었다(§507).

## 7. 우선순위를 어떻게 정하는가 — 척도가 세 번 바뀌었다

### 7.1 1세대 — 칸 수가 아니라 칸/재료로 잰다

8차 파동 착수 시점에 빈칸이 5,150개였다. 물성별로 세면 **밀도가 893칸**으로 압도적 1위다.
여기까지는 누구나 안다. **그런데 그 893칸의 원인은 재료 134종뿐이었다.**

```
893칸 ÷ 134종 = 재료 하나당 6.7칸
```

밀도는 구조·낙하·열전달·워피지·결로·초탄성·접착 **거의 모든 해석의 필수 물성**이라
한 번 채우면 여러 칸이 동시에 닫힌다. 게다가 근거를 찾기도 가장 쉽다
(결정구조 논문의 계산밀도, 벤더 비중, 같은 계열 값).

**134종에 배치 하나를 붙였더니 전체 셀 채움이 72.2% → 82.3%로 10%p 뛰었다.**
**재료 수가 아니라 칸/재료로 우선순위를 잡은 것이 맞았다.**

### 7.2 2세대 — "1칸 부족 재료"를 센다. 그리고 그 척도도 죽었다

13차판 이 문서가 예고를 적어 두었다 —
*"칸/재료가 1.00으로 평평해졌다 … 기본 물성이 닫히면 이 척도는 스스로 수명을 다한다."*
그리고 *"이 척도(1칸 부족)도 수명이 거의 다했다"*고 덧붙였다.

**예고는 실현됐다. 다만 예상한 방식이 아니었다.**

13차에는 빈칸 있는 재료가 **55종**이었고 그중 **44종이 딱 1칸**이었다.
지금은 빈칸 있는 재료가 **473종 / 864종**이고 **1칸 부족은 23종**뿐이다.

| | 13차 | 54차 |
|---|---:|---:|
| 격자 대상 재료 | 544 | 864 |
| 빈칸 있는 재료 | 55 | **473** |
| 그중 1칸 부족 | 44 (80%) | **23 (5%)** |
| 남은 빈칸 | 376 | **7,769** |

**"1칸만 채우면 해석이 열린다"가 5%에서만 참이다.**
남은 재료의 대다수는 **코어를 통째로 비운 신규 재료**이고, 그건 한 칸을 뚫어서 열리지 않는다.
예외가 하나 있다 — **전기·EMI는 남은 243종 전부가 1칸 부족**이다(택일군 하나짜리 해석이라 그렇다).

**그래서 1·2세대 척도는 둘 다 은퇴했다.** 둘의 공통 전제가 *"격자가 안 변한다"*였는데
16차 이후 격자가 재료 544 → 864로 커졌다. **분모가 움직이는 동안에는 잔여 기반 척도가 서지 않는다.**

### 7.3 3세대 — 계통으로 자르고, 빈칸을 갈래로 갈라라

지금 실제로 우선순위를 정하는 것은 **§5의 계통 축과 §6의 네 갈래 분해**다.
그리고 그 둘은 순서가 있다.

```
① 계통을 골라 코어 채움률을 **다시 재라** (인계된 채움률은 셋 중 하나가 틀린다 — §12)
② 그 계통 재료의 attributes 를 읽어라  ← 판정이 이미 있을 수 있다(magnetics 175칸)
③ 남은 빈칸을 네 갈래로 갈라라        ← packaging 444 · pcb 391
④ ④갈래(진짜 남은 것)와 '미확인'만 표적이다
```

**여기서 나오는 수가 우선순위다.** pcb는 391칸 중 7칸이었고, packaging은 444칸 중
등급 미확정 92 + 정상 0/7이 21이었다. **채움률만 보면 둘 다 최우선 표적으로 보인다.**

그리고 **막힌 칸이 키 때문이면 그건 채굴 배치의 일이 아니다**(§6.3) —
키를 여는 배치를 따로 세워라.

### 7.4 우선순위를 잘못 잡았던 실제 사례

**지표가 틀리면 우선순위도 틀린다.**
낙하가 22%로 꼴찌일 때 "항복강도가 병목"이라고 판단해 **에이전트 하나를 통째로 썼다.**
결과는 "채울 수 없는 항목"이었다 — GF 강화 등급은 항복점을 애초에 재지 않는다.
지표를 고치니 낙하는 74%였고 **진짜 병목은 율속(305종 전무)**이었다(58장).

**같은 유형이 54차에 다시 났다.** 채움률 최저인 magnetics를 표적으로 고를 뻔했는데
그 175칸은 이미 판정이 끝나 있었다(§6.2). **두 번 다 "숫자가 낮다"를 "일이 남았다"로 읽은 것이다.**

### 8.3 지표 하나만 보면 속는 자리 — 실제 수치로

**(가) 셀 채움만 보면 실측 두께가 안 보인다.**

**(다) 셀 채움과 재료 준비가 크게 갈리는 자리가 진짜 병목이다.**
피로·수명은 셀 55.1%인데 준비 23.1%다. 낙하는 63.8% 대 45.9%다.
**재료마다 비어 있는 칸이 다르면 이렇게 벌어진다.**
반대로 전기·EMI는 71.8% 대 71.8%로 완전히 같다 — 택일군 하나짜리 해석이라
채운 칸이 곧 준비된 재료다.

**(라) "적용 대비 준비"는 분모를 줄여 올린 수치다.**
세라믹에 변형률-수명 피로계수를 요구하면 그 재료는 영원히 준비 안 됨으로 남는다.

피로가 23.1% → 27.2%로 오르는데, **이 상승은 수집 성과가 아니라 정의다.**
그래서 두 열을 반드시 나란히 둔다.

**(마) 그리고 어느 지표도 "그 칸이 왜 비었는지"를 말하지 않는다.**

**실제로 캘 수 있는 것은 각각 극소수**다. 지표를 표적 선정에 바로 쓰면 안 된다.

### ② 반례 검증 — 선언은 주장이 아니라 반례로 무너진다

"이 물성은 이 재료군에서 애초에 발표되지 않는다"는 선언은 **두 조건을 다 만족할 때만** 유효하다.

1. 문서에 기록된 사유가 있다(`UNFILLABLE`에 적혀 있다) — "아직 못 찾았다"와 구분한다.
2. **그 군의 어느 재료도 그 물성을 실측으로 갖고 있지 않다 — 반례가 0이다.**

값이 하나라도 들어오면 그 쌍은 **자동으로 부재에서 빠진다.**

- 처음 `UNFILLABLE`을 그대로 믿었더니 **102칸이 "부재인데 값이 있음"으로 걸렸다.**
  벤조페논은 상용 화학물질이라 CRC에 밀도가 있고, `laminate`·`coverlay` 매처가 비열을 가진
  재료까지 잡았다. **선언 16개 중 13개가 반례로 무너졌다**(70장).
- **반례는 실측(tier≤3)만 인정한다.** 8차에서 아크릴 폼 테이프 11종에 항복강도 tier4
  가정값을 넣자 "점착테이프에는 항복점이 물리적으로 없다"는 선언이 **자동 은퇴했다.**
  **우리가 만든 가정이 우리의 부재 선언을 지우면 안 된다**(71장).
- **페이월은 부재가 아니다.** 접근 문제는 언제든 열릴 수 있으므로 분모에 남긴다.

### ④ 원문 문자열 대조 — 저장한 숫자가 인용 출처에 실제로 있는가

수집을 마친 뒤 **각 행의 값이 인용 출처 원문에 문자열로 존재하는지** 검사하는 스크립트를 돌린다.
5차 파동에서 한 배치가 자발적으로 만들었고, 그 뒤 브리프의 작업 습관이 됐다.

| 잡은 것 | 실체 |
|---|---|
| Al2024-T3 표면에너지 35.3 mJ/m² (66장) | 값은 맞는데 **엉뚱한 논문에 붙어 있었다** |
| Lexan FR25A 탄성계수 (68장) | SABIC 매뉴얼 출처에 붙었으나 실제는 arXiv 논문 |
| FR-4 밀도 (68장) | 값은 `g-10.pdf`에 인쇄됐는데 블록 URL이 `fr-4.pdf`. **인제스트는 블록당 출처 하나만 저장하므로 그대로면 엉뚱한 문서에 붙는다** |
| 아크릴 PSA 열전도율 0.176 (71장) | **원문 전문에 `0.176`이 0회 등장**. notes가 주장한 "0 wt% 대조군 실측"이 거짓이었다 |

**여기서 나온 교훈이 이 문서에서 가장 중요한 것 중 하나다.**
notes가 주장하는 근거를 원문에서 확인하지 않으면 **틀린 값이 아니라 틀린 근거가 번진다.**
**값은 검산으로 걸리지만 근거는 안 걸린다.**

### ⑤ 규칙 6 — 기존 값과의 자릿수 대조

§3의 규칙 6이 그대로 검증 장치다. **넣기 전에 DB에서 그 재료의 기존 값을 먼저 확인한다.**
값 하나만 보면 완벽한데 그 재료의 카드 안에서 앞뒤가 안 맞는 경우를 잡는다.

### ⑥ 대장 점검 — 폐기 판정이 헛돌거나 잘못 걸리나

폐기 대장은 **여러 배치가 동시에 쓰는 파일**이다. 읽어서 고쳐 쓰는 방식이면 병렬 파동이
서로를 덮어쓴다. 그리고 대장이 조용히 망가지면 **두 방향으로 손해**다.

- 줄이 헛돌면 → 버린 논문을 다음 파동이 다시 연다(일 낭비)
- **줄이 잘못 걸리면 → 멀쩡한 논문이 표적에서 사라진다**(논문을 잃는다)

`verdicts_check.py` — 현재 **대장 98줄 · 파싱 98 · path 있는 줄 82 · 이상 0**.
남은 경고 하나가 이 장치의 값어치를 보여준다 —
*"제목으로는 걸리지만 `path`가 없는 줄 1개 — 제목 표기가 흔들리면 죽는다."*
**대장은 append-only다.**

### ⑦ 병합 예행 — 고친 것이 운영까지 가나

**이 장치가 43차 이후 가장 많이 잡았다.** 병합기는 자연키로 대응행을 찾고, 찾으면
`remap`만 하고 지나간다 — **삽입만 한다.** 그래서 "기존 행의 수정"으로 표현되는 것은
전부 조용히 버려진다. 같은 결함을 **다섯 번** 다른 얼굴로 만났다(§464·522·536·579 + §594).

| 얼굴 | 무엇이 안 갔나 | 실측 |
|---|---|---|
| ① 재료 `attributes` | 계통 태그 346종 | 운영 태그 191/2493에서 **병합 후에도 191** |
| ② 물성값 정정 | `correction_reason`이 붙은 정정 | 분기 없으면 `added 36` — **틀린 옛 행과 고친 새 행이 나란히 남는다.** 고치기 전보다 나쁘다 |
| ③ 값 이동 | 자연키에 `material_id`가 들어 있다 | 이동한 행이 운영에서 새 행이 된다 |
| ④ 출처 이동 | 자연키에 `source_id`가 들어 있다 | 같은 지문 |
| ⑤ 조건 칸 덮어쓰기 | `_before_correction`을 안 남기면 사전 대조가 언제나 어긋난다 | `correction_misses 4 · source_move_misses 4` → 표시 남기면 **둘 다 0** |

**예행의 값어치는 `added 0` 한 줄에 있다.** 49차 KB의 실측이다.

```
1차 병합 (src=정정본 · dst=정정 직전 백업)
  property_value  added 0 · matched 41368     ← 새 행이 안 생긴다
  value_corrections_total 36                  ← 운영 행 36개를 UPDATE 했다
  correction_misses (출력 없음 = 0) · fk_violations 0
2차 병합 (같은 쌍을 한 번 더)
  added 0 · value_corrections 0 · misses 0    ← 자연키가 걸려 멱등하다
```

**절차가 이 저장소에서는 남들과 반대다.** 카탈로그 적재기는 dev를 거치지 않고
**라이브 DB에 직접 쓴다.** 그래서 "운영 자리에 놓을 정정 직전 상태"는 적재 뒤에는 어디에도 없다 —
**`--apply` 전에 `sqlite3.backup`으로 떠 둬야 한다.** 순서를 놓치면 예행 자체를 못 만든다.

**그리고 `*_misses`가 0이면 출력이 아예 없어서 "안 봤다"와 구별이 안 된다.**
요약 JSON에 `correction_misses_total` 키가 있는지로 봐라.

### ⑧ 마이그레이션 예행 — 옛 리비전 DB로 해라

Knoop 이관 마이그레이션을 운영 DB 사본에 예행해 보니
**`mechanical.hardness_knoop` 정의 행이 아예 없었다**(§482). 개발 DB에는 부팅 시드가 넣어 둔다.

→ **이관 마이그레이션은 대상 키 정의를 스스로 보장해야 한다.**
**예행은 반드시 옛 리비전 DB로 해라.** 개발 DB(이미 head)로 돌리면 이 함정이 안 보인다.

**되돌리기도 검증 대상이다**(§595). 54차 PB의 `downgrade` 초판이 `d.pop(MARK)`였는데,
파일을 고치려 라이브를 되돌리자 **앞 파동의 계보가 60행에서 통째로 사라졌다.**
**되돌리기가 지운 것은 자기 표시가 아니라 남의 계보였다.**

1. `downgrade`는 `<칸>_before_correction`**에서 복원**해라. 없으면 **지우지 말고 건너뛰어라.**
2. **실행 전에 그 파일이 이미 적용된 판인지 확인해라** — 적용판과 수정판의 `downgrade`가
   다르면 되돌아가지 않는다.
3. **병렬 파동에서는 통째 복원이 불가능하다.** 고칠 칸만 집어라.

### ⑨ 카드 회귀 — 소비자 산출물이 안 변했나

**대표값·조건·순위를 건드리는 모든 작업의 합격 조건이다.**
`build_cards`를 **전 재료 2,654종**에 돌려 카드 수·종류별 분포·재료별 구성을 대조한다.

```
역학 742장 — MAT_ELASTIC 503 · PIECEWISE_LINEAR_PLASTICITY 178
              GENERAL_VISCOELASTIC 35 · VISCOELASTIC 26
열   584장
```

**회귀 계약은 한 문장이다 — "안 고르면 지금과 똑같다."**
51차 MC가 카드에 후보 지정 기능을 열 때 이 대조로 전부 불변임을 확인했다(§550).

### ⑩ 대표값 회귀 — 순위가 안 뒤집혔나

조건 어휘를 통일하거나 판정을 박는 작업은 **조건 수를 바꾼다.**
그런데 `_rep_rank`의 다섯 번째 자리가 `len(conditions)`다 —
**한 군의 일부 행에만 칸을 더하면 대표값이 뒤집힌다.**

`correction_reach.py plan`이 전/후를 나란히 낸다. 현재 실측이다.

```
대표값 전/후 (후보 둘 이상 6,339군)  대표 행 변동 0군 · 대표 값 변동 0군
```

**라이브 스냅샷에 `_rep_rank`를 그대로 옮겨 심은 하네스로 41,396행 전수 불일치 0을 먼저
확인해야 그 숫자를 믿을 수 있다**(§545). 순위 규칙은 `backend/tests/test_rep_rank.py`에
21개로 못박아 두었다.

### 9.1 검사가 오탐을 냈을 때의 규율

여섯 번 있었고, 대응이 매번 같았다 — **검사를 느슨하게 만들기 전에 오탐의 원인부터 본다.**

| 오탐 | 원인 | 고친 방식 |
|---|---|---|
| `가정값인데 tier4 아님`이 SmCo 3건을 잡음 (68장) | 조건에서 **부분문자열** `assumption`을 찾는데 `direction: "bulk effective (isotropic assumption)"` 같은 **방법 서술**에 걸렸다. 값은 초음파 실측 | 구조화된 표지 `"assumption": true`만 보도록 좁혔다. **검사는 산문이 아니라 구조를 봐야 한다** |
| `Prony 항번호 없음`이 36건 오탐 (72장) | **장기계수 E∞는 Prony 항이 아니라 평형값**이다. 급수는 E(t)=E∞+ΣEᵢexp(−t/τᵢ)이고 E∞는 급수 밖이라 항번호가 없는 게 맞다 | 검사에서 제외 |
| `recaptcha` 문자열로 실패 판정 (69장) | **정상 페이지의 폼 스크립트에도 그 문자열이 있다.** 한 배치가 caplinq 물성표 6건을 그렇게 잘못 버렸다 | 판정을 **"찾는 제품명이 본문에 실제로 있는가"**로 바꿨다 |
| `direction` 문자열이 다르면 경고 (51차 MC) | **39종에서 걸리는데 방향이 실제로 다른 것은 1종**뿐이다 — 나머지 38종은 같은 방향의 다른 표기다(`'MD'` 대 `'in-plane (biaxially oriented film; MD/TD not distinguished by the source)'`) | 분류를 포기하고 **후보를 값·조건·행번호 그대로 보여줬다.** 분류기 정확도 2.6% 대 공개 64%다. **자유형식 조건은 분류하지 말고 보여줘라**(§551) |
| `451` 중앙값 가드가 부정문에 걸림 (44차) | **브리프를 지킨 배치가 벌을 받고 있었다** — notes에 *"중앙값이 아니다"*라고 적으면 가드가 문자열로 걸었다 | 로더를 고쳤다. **가드가 산문을 읽으면 부정문에서 반드시 뒤집힌다** |
| `%` 뒤에 `\b`가 성립하지 않음 (52차) | 정규식이 **조용히 0건**을 냈다 | 단어경계 대신 명시적 경계로 바꿨다. **0건은 "없다"가 아니라 "정규식이 안 걸렸다"일 수 있다** |

그리고 반대 방향 — **가드가 좁아서 정상값을 버린 사례가 셋**이다.
굴절률 가드 0.8~5.0이 c-Si(5.613 @400 nm)와 TiN(0.7946 @633 nm)을 버렸고,
유전율 상한 1e5가 MnZn 페라이트의 정상값 14만(입계 효과)을 버렸고,
Prony 완화시간 상한이 마스터커브 피팅값 1e14 s를 버렸다.
**가드는 자릿수 사고만 잡게 두고 물리 범위를 좁게 잡지 말 것.**

| **합** | **3,972** | **2,862** | |

**행이 같은 게 아니라 선택기가 못 보는 것이었다.**
일률로 "적재 순서"라 적으면 대부분에서 **틀린 설명**이고,
매번 뜨는 같은 경고는 무시하는 법을 가르친다.

**그리고 임계값을 올리는 것은 소음 대책이 아니다.** 동률의 값차 중앙값이 34.5%(p25 12%)라
1%→10%로 올려도 3,972 → 2,862, **28%만 준다.** 동률은 애초에 아슬아슬한 차이가 아니다.
진짜 소음 대책은 셋이다 — **대표행에만** 붙인다 · **원인을 이름으로 가른다** ·
갈래마다 문구를 달리한다.

> **인계 검산** — 51차 MB의 보고는 *"3,642건 중 condition_axis 3,213(88%) · multi_term 394 ·
> **indistinguishable 35**"*였다. **지금 분류기로는 재현되지 않는다.**
> 모수가 3,642에서 3,972로 커졌고(행이 늘었다), `indistinguishable` 부류 자체가 사라졌다
> — 분류기가 세 번 고쳐지며 그 군이 `다른조건`·`산포범위`로 흡수됐고 지금 **미분류는 0**이다.
> **§599가 말한 그대로다 — 분류기를 고쳤으면 이미 박힌 판정을 다시 세라. 판정은 값처럼 늙는다.**

### 10.3 순위를 더 만들지 않았다 — 축을 더하는 시도를 두 번 재고 둘 다 버렸다

**§543** — 선택기에 `method`를 넣어 봤다. 라이브 41,368행으로 쟀더니 26쌍이 뒤집혔고
**개선은 4건**이었다. **§544** — "온도 미기재 벌점"을 재 봤더니 67쌍이 뒤집혔고 개선은 1건이었다.

**규율 — 순위에 축을 더하고 싶으면 먼저 전수로 재라.** 재 보고 안 넣었다.

### 10.4 세 번째 길 — 드러내고 고르게 한다

51차 MC가 순위를 그대로 두고 **호출자가 후보를 고르게** 열었다(§550).

- **선택자는 두 형태면 충분하다** — `#행번호`(카드 주석이 그 번호를 적어 준다)와
  `조건키=값`(**부분일치**). 정확일치로는 못 쓴다 —
  라이브의 `direction` 값이 자유형식 **255종**이고 54종은 40자 넘는 산문이다.
- **슬롯마다 따로 골라야 한다.** 카드 슬롯의 대표값 방향이 갈린 재료 212종에서 가장 흔한 쌍이
  **(열전도율, 선팽창) 146종**이다. 재료 하나에 방향을 강제하면 그 방향 값이 없는 칸이 통째로 빈다.
- **없는 후보는 거부한다.** 대표값으로 조용히 떨어지면 해석자는 자기가 고른 값을 쓴 줄 안다.
  거부 메시지에 **실제 후보 목록**을 넣어야 고칠 수 있다.
- **후보 목록은 새 조회 경로를 만들지 말고 덱을 뽑는 그 호출이 같이 돌려줘라**(`list_choices`).
- **회귀 계약은 하나다 — "안 고르면 지금과 똑같다"**(§9의 ⑨).

그리고 카드가 스스로 알린다. 지금 **역학 카드 742장 중 122장**이 RO·E·PR·SIGY 네 칸 중
하나 이상에 이 주석을 단다.

```
$ ※ 주의: 대표값이 동률이다 — E 는 순위가 같은 후보 3개에서 적재 순서로 골랐다 (진 쪽 70000, 69300)
```

**카드는 그대로 선다. 주의는 카드를 막지 않는다.**

### 10.5 대안을 여는 비용은 조건 사본이 대부분이다

첫 구현은 진 후보의 `conditions`를 통째로 실어 응답이 26~81% 부풀었다.
**처방이 자리마다 다르다**(§552).

- **상세** — 전 행이 응답에 이미 있으니 조건 차이를 서버가 낼 필요가 없다. 화면이 계산한다(+7%).
- **Ashby** — 대다수가 후보 1개니 **그럴 땐 필드를 아예 안 붙인다**(+6%).
- **비교** — 진 행이 응답에 없으니 서버가 내되 조건 사본 대신 **다른 칸만·2건까지·40자 클립**(+35%).
- **MCP 목록·검색** — 수만 낸다. LLM 응답에 후보 값을 실으면 부풀기만 하고 판단에 안 쓰인다.

**그리고 화면은 값을 감춘 적이 없었다.** 상세는 예전부터 전 행을 다 보여주고 있었고,
빠져 있던 것은 정확히 **"이 중 어느 것이 카드·비교·Ashby로 나가는가"**였다.
**대안 노출 과제를 받으면 먼저 "정말 값이 안 보이는가"를 확인해라 —
대개 안 보이는 것은 값이 아니라 표시다.**

## 11. 정정·판정·이동 — 값을 지우지 않고 표시한다

**이 카탈로그는 값을 지우지 않는다.** 틀린 것을 고칠 때도, 판정을 내릴 때도,
다른 재료로 옮길 때도 **표시를 남긴다.** 그래야 되돌릴 수 있고 계보가 남는다.

### 11.1 지금 무엇이 얼마나 박혀 있나

`conditions` 안의 표시성 칸을 세면 이렇다(41,396행 중).

| 표시 | 행 | 무엇인가 |
|---|---:|---|
| `correction_reason` · `corrected_by` | **22,754** | 정정된 행. 사유가 **값과 함께** 남는다 |
| `verdict_tie_axis` · `verdict_tie_note` | **10,907** | 동률 판정(§10.2). `*_before_correction` 짝도 같은 수만큼 있다 |
| `assumption: true` | **4,404** | 가정값 표지. **전부 tier4다**(§2.2). `assumption: false`가 109행 더 있는데 전부 tier2·3이다 — **"가정이 아님을 명시한" 행이므로 세지 않는다** |
| `moved_from_source` | 203 | 출처 이동 계보 |
| `verdict_duplicate_of` | 63 | 중복 판정 |
| `not_printed` | 139 | 그 시트가 그 칸을 안 찍는다 |
| `magnitude_suspect` | 5 | 인쇄값이어도 해석 입력으로 바로 쓰면 안 된다 |
| `pair_incomplete` | 13 | 짝의 반쪽만 있고 **사유가 적혀 있다**(§9의 ①) |
| `moved_from_material` | 2 | 재료 이동 계보 |

### 11.2 정정 경로가 지켜야 할 여섯

47차까지 적재기는 **삽입만 했다.** 그래서 세 배치가 값이 틀렸음을 **증명하고도
고치지 못하고 브리프에 적어 두고 지나갔다.** 47차 IB가 명시적 정정 경로를 냈다(§521).

**"덮어쓰지 않는다"를 없애지 않았다.** 그건 배치가 더 좋은 값을 뭉개는 것을 막는 보호장치다.
같은 재료·같은 키에 값이 또 오면 **지금과 똑같이** 삽입하거나 건너뛴다. 연 것은 그 옆의 문 하나다.

| 성질 | 어떻게 |
|---|---|
| 암묵적 정정 없음 | JSON이 `corrections` 배열로 **선언**했을 때만 돈다. `materials`로는 절대 안 고쳐진다 |
| 대상 못박기 | 행 id, 또는 재료+키+조건(+값·출처). **2건 이상 걸리면 거부** — 우리가 고르면 그건 우리 판정이다 |
| 사유 필수 | `reason` 10자 미만이면 거부. `conditions.correction_reason`으로 **값과 함께** 남는다 |
| 되돌리기 | 바뀐 칸마다 `<칸>_before_correction`. 조건은 **칸 단위로** 남긴다 |
| 등급 상향 | `evidence`를 **사유와 별도로** 요구한다. **t1은 method가 measured·digitized여야 한다** |
| 드라이런 | `--apply` 없으면 옛값→새값만 출력하고 한 칸도 안 쓴다 |

**가드는 삽입과 같은 것을 쓴다** — 단위·범위·퍼센트. 정정이 가드의 우회로가 되면 안 된다.
그리고 **정정 결과가 다른 행과 (재료·키·출처·조건)이 같아지면 거부한다**(중복은 정정이 아니다).

- **`property_key`·`material_id`는 못 고친다.** 그건 정정이 아니라 **이동**이다.
- **정정을 두 번 하면 앞 정정의 사유가 지워진다**(§573). 칸을 늘리지 말고 **그 칸 안에 쌓아라.**

### 11.3 합격 조건은 하나다 — 운영까지 가는가

**§9의 ⑦이 이 장의 시험이다.** dev에서 고친 것이 병합기를 통과하지 못하면
그 정리는 없었던 일이다. 실제로 다섯 번 그랬다(§464·522·536·579·594).

**막고 있던 것은 데이터가 아니라 경로였다.**
병합기의 정정 탐색축 `(재료·물성키·출처·옛 값)`이 라이브에서 유일하지 않다 —
**4,265행 1,832군**이 그렇다. 그래서 52차 NA가 조건 어휘를 통일하다
**691군 5,265행에서 막혔다.**

그 뒤 두 걸음으로 풀렸다.

1. **판정 키를 자연키에서 빼라**(§564). 판정은 값이 아니므로 자연키에 있을 이유가 없다.
   `자연키 − verdict_*`로 재면 **전 행이 유일하다.** 예행 `verdict_misses` 2,254 → 0.
2. **조건을 파싱해 사전으로 대조하라**(§579·588). 그런데 정정 분기에서는 한 걸음이 더 든다 —
   **정정이 바꾼 칸이 조건 그 자체**라 **정정 전 조건을 표시로 되돌려** 대조해야 한다.
   실측 **691군 → 71군**, 620군 4,989행이 열렸다.

현재 남은 막힘이다.

```
python3 backend/scripts/catalog/correction_reach.py plan

-- 막힘 --
  조건 대조 넣기 전 :   71군    276행   ← 52차 NA 가 포기한 수
  조건 대조 넣은 뒤 :   71군    276행
-- 여전히 막힌 사유 --
     134행  옛 컬럼 표시 `method_before_correction` 가 탐색축을 틀리게 만든다
-- 대표값 전/후 (후보 둘 이상 6339군) --  대표 행 변동 0군 · 대표 값 변동 0군
```

**그리고 이동·정정이 건드리는 칸이 이미 있던 칸이면 `<칸>_before_correction`을 반드시 남겨라**(§594).
안 남기면 사전 대조가 언제나 어긋난다. `null`은 "정정 전에 이 칸이 없었다"는 뜻이다.

### 11.4 판정을 조건에 적을 때의 함정 넷

**우리 글을 조건에 적으면 조건을 *읽는* 코드 전부가 오염된다.** 같은 병을 네 번 만났다.

| 함정 | 무엇이 깨졌나 |
|---|---|
| 판정문이 **조건 수**로 세어진다(§557) | `_rep_rank` 다섯 번째 자리가 `len(conditions)`다. 한 군의 일부 행에만 칸을 더하면 **대표값이 뒤집힌다** |
| 판정문이 **문자열 검색**에 걸린다(§571) | `assumption` 부분문자열 검사가 방법 서술에 걸린 것과 같은 지문이다 |
| 판정문이 **조건축으로 분류된다**(§557) | §10.2의 세 갈래가 무너진다 |
| 되돌리기 표시가 **순위와 병합기를 동시에** 망가뜨린다(§558) | 셋을 같이 고쳐야 한다 |

**규율 둘.**
① **한 군의 모든 행에 같은 수의 칸**을 더해라.
② **전파 불가능한 군은 건너뛰어라.** 병합기가 운영행을 못 찾으면 **운영에 새 행을 만든다.**

### 11.5 이동과 묘비

값이 다른 재료·다른 키로 가야 할 때가 있다. 그건 정정이 아니다.

- **묘비를 세운다** — `merge_verdict: "moved"` + `merge_moved_to`.
  **`merge_moved_to`에는 재료 id가 아니라 이름을 적어라**(§535).
  id를 적으면 운영에서 **엉뚱한 재료를 가리킨다.**
- **묘비가 없으면 무결성 검사가 `물성값 0인 재료`로 잡는다**(§9의 ①). 그게 맞다 —
  묘비 없는 껍데기는 다음 파동이 "묘비다"라고 오독한다.
- **삭제는 dev에서만 사라지고 운영에는 영원히 남는다**(§565). 병합은 비파괴다.
  **지운 행은 운영에 그대로 남고 되돌아오지도 않는다.**
- **죽은 출처의 틀린 메타는 못 고친다**(§597). `source.doi`가 UNIQUE라
  `NULL`로 비우면 자연키가 바뀌어 **운영에 껍데기가 하나 더 생긴다.**
  → **남는 위험을 명시해서 넘겨라.**

## 12. 인계 규율 — 수를 넘기지 말고 경로를 넘겨라

**이 장이 44차 이후 가장 비싸게 배운 것이다.**

### 12.1 인계 수치는 예외 없이 검증 대상이다

| 파동 | 인계 | 실측 | 어긋난 이유 |
|---|---|---|---|
| 44차 (§479) | 막힌 칸 **79** (세 배치 합) | **67행** | FB의 `리틀턴 18`이 재현되지 않는다 · FC의 3칸은 **시트가 디스크에 없다** |
| 46차 (§505) | 지시문의 '주의' 둘 | **둘 다 틀렸다** | `875 g/L`은 면적당 무게가 아니라 **별개 제품의 밀도**였고, `1.77`은 AE44가 아니라 **AM50A** 값이었다 |
| 47차 (§528) | OLED 소분자 **8종** | **172종** | 화면이 거른 것은 안 보인다(§5.3) |
| 48차 (§533) | **26 · 40 · 24**칸 | **12 · 36 · 112** | 하나는 다른 물성의 수를 베꼈고, 하나는 **마커를 세었고**, 하나는 배합 수를 곱하지 않았다 |
| 54차 (§587) | 계통 채움률 넷 | **셋이 틀렸다** | 전부 **재료 수**에서 어긋났다 — 잰 시점 이후에 배치가 재료를 더 넣었다 |

**셋의 어긋남이 서로 다른 종류다.** 즉 **한 가지 실수 패턴을 고쳐서 될 일이 아니다.**
그리고 **어긋나는 방향이 양쪽 다** 나온다(줄기도 하고 22배 늘기도 한다).

**규율 — 인계 수치는 그림·표·DB를 열어 다시 세기 전까지 "규모의 힌트"일 뿐이다.**
계통 채움률은 다시 재는 데 10초면 끝난다.

### 12.2 그러면 무엇을 넘겨야 하는가

**54차 PA에서 인계가 네 자리 다 맞은 첫 사례가 나왔다**(691군 5,265행 · 71군 276행 ·
620군 4,989행 · 사유 71/71).

이유가 분명하다. **53차 OA가 넘긴 것이 수가 아니라 경로였다** —
*"막힌 칸이 몇 개다"*가 아니라 ***"어느 분기가 어느 축으로 못 찾는다"***였다.

**표적을 넘길 때 그 수를 만든 경로를 같이 넘겨라. 그러면 다음 배치가 세는 대신 고친다.**
수만 넘기면 받은 쪽이 먼저 다시 세야 하고, **그렇게 넘긴 인계는 예외 없이 틀렸다.**

부수 규율 셋이다.

- **막힌 값을 넘길 때는 `attributes`에 전부 넣어라.** 절반만 넣으면 다음 배치가
  "인계에 적힌 수"와 "실제로 남아 있는 수" 사이에서 원본을 다시 열게 된다.
- **넘길 수 없으면 원본 경로를 그 재료의 notes에 적어라.**
- **판정은 그 판정을 읽을 코드가 보는 자리에 남겨라**(§6.2). 자유 키에 있으면 집계가 못 읽는다.

### 12.3 조정자의 '주의'가 틀리면 배치가 멀쩡한 값을 버린다

**표적이 틀리면 배치가 헛돌 뿐이지만, '주의'가 틀리면 배치가 값을 버린다.**
지시문의 경고는 배치에게 "이 방향으로 의심하라"는 편향을 준다 — 그래서 표적보다 더 위험하다.

- **조정자가 확인하지 않은 것은 경고로 적지 마라.** *"이럴 수 있으니 확인해라"*는 되고
  *"이것은 X다"*는 안 된다. **앞의 것은 검증을 시키고 뒤의 것은 검증을 대신한다.**
- **아는 값을 적을 때는 출처를 같이 적어라.**

### 12.4 부정문을 판정문에 쓸 때는 그 부정을 전수로 확인해라

**같은 병이 훨씬 크게 있었다**(§570).
동률 분류기가 "한쪽에만 있는 축이 남았다"를 보고 바로 **조건미기재** —
*"이 축이 한쪽에만 적혀 있다"*로 떨어뜨렸는데, 그 군에 **다른 축이 양쪽에 다 적혀 있고
값까지 다른 경우가 119군 중 77군**이었다.

전수 실측으로 고쳤다 — **조건미기재 119 → 42 · 다른조건 2,406 → 2,486,
다른 부류는 한 군도 안 움직였다.**

> **긍정문은 틀려도 다음 사람이 값을 보고 고친다.
> 부정문은 "찾을 것이 없다"고 말하므로 아무도 안 본다.**

같은 이유로 **"전부 X다"라는 인계는 수보다 먼저 의심해라**(§569).
그리고 **"접근 부재"로 적힌 것은 다시 두드려라** — 열 표적 중 여섯이 열렸고 판정 넷이 틀렸다(§517).

## 13. 함정 지도가 축적되는 방식 — 왜 실패를 남기는가

### 13.1 실패는 네 곳에 나눠 적는다

| 문서 | 무엇을 담나 | 목적 |
|---|---|---|
| `COLLECTION_BRIEF.md` **6절** | **판정 함정** — 어떤 표·사이트·표기를 조심할 것인가 | 다음 배치가 같은 값을 다시 집지 않게 |
| `BLOCKED_SOURCES.md` | **접근 실패** — 유료(A)/로그인(B)/미공표(C)/삭제(D)/그림뿐(E) | 같은 곳을 다시 뒤지지 않게 |
| `PROPERTY_DATA_HISTORY.md` | **경위** — 무엇을 시도했고 왜 틀렸나(38차까지) | 판단의 근거를 재구성할 수 있게 |
| **`COLLECTION_BRIEF_CORPUS.md`** | **39차 이후의 함정 지도 600절.** 이 문서의 §5~§12가 전부 여기서 나왔다 | 파동이 얻은 것을 잃지 않게 |

**그리고 이 코퍼스 문서 자체가 함정에서 나왔다** — 14~17차 파동은 이 내용을
세션 스크래치패드에 두었다가 세션이 끊기면서 **통째로 잃었다.**
**파동이 얻은 함정 지도는 반드시 저장소에 남겨라.**

브리프 정본의 첫 문장이 이렇게 적혀 있다 —
**"이 문서의 값어치는 규칙이 아니라 6절의 함정 지도에 있다. 각 항목은 전부 실제 사고 기록이다."**

### 13.2 실제로 시간을 아낀 증거

**(가) 검산 방법이 전파돼 다음 파동에서 즉시 작동했다.**
6차 파동이 FR-4 열물성 표를 **같은 표의 알려진 재료(Sn63Pb37 밀도 1,890)로 검산해** 버렸다.
이 방법을 브리프 6절에 "표에 있는 알려진 재료로 검산하라"로 박았고,
**8차 파동은 같은 방식(혼합물 물리 상하한)으로 EMC 논문 표 두 건을 즉시 걸렀다.**
두 건 다 같은 표의 다른 행(Si 712, PCB 920, Al 900)은 완벽했으므로,
검산 규칙이 없었으면 표 전체를 신뢰했을 것이다.

**(나) 복사 계보 규칙이 여러 건을 한 번에 버리게 했다.**
PV 적층 물성표가 세 문헌에 바이트 단위로 복사돼 있음을 확인한 뒤로,
**같은 숫자 조합이 여러 논문에 나오면 한 건만 검산하고 나머지를 같이 버린다.**
독립 확인처럼 보이는 것을 세 번 검증하는 낭비가 사라졌다.

**(다) 아카이브 회수분이 다음 파동의 첫 조회처가 됐다.**
9차 피로 배치가 `fde.uwaterloo.ca`를 무지연으로 610쪽 받고 **IP 차단**을 맞았다.
Wayback으로 26개 세트를 회수해 `FDE_FATIGUE_ARCHIVE.md`에 표로 남겼고,
문서 첫 줄이 **"다음 파동은 이 표를 먼저 보고 필요한 것만 Wayback에서 다시 받아라"**다.
같은 문서가 **회수하지 못한 것**(AA7050-T7351, PPS-glass)도 명시해
다음 파동이 그것을 찾느라 시간을 쓰지 않게 했다.

**(라) 광맥 하나를 지도에 올린 것이 한 배치를 통째로 해결했다.**
브리프 2절에 `accudynetest.com`의 `polytable_03.html`이
**"38종 폴리머의 임계표면장력과 물 접촉각을 한 행에 나란히 인쇄해 두 키를 한 출처로 동시에 닫는다"**고
적혀 있다. 9차 젖음성 배치가 **182종 중 179종을 닫았고 그중 133종(74%)이 여기서 나왔다.**

**(마) 브리프의 "성공처럼 보이는 실패" 목록이 잘못된 결론을 막았다.**
`hdl.handle.net`이 862바이트 스텁을 준다는 항목이 없었다면
7차 파동이 **그 스텁을 근거로 "그 논문에 값이 없다"고 결론냈을 것이다.**

### 13.3 0건 보고를 실패로 읽지 않는다

**"더 찾아도 안 나온다"를 확정하는 것도 성과다.**
3차 파동의 0건 보고 세 건이 전부 값 있는 결과로 바뀌었다 —
점탄성 0건은 사유가 등급 불일치임을 밝혀 제약을 풀자 4종 115항이 나왔고,
무기 비열 0건은 CCL 벤더 6곳이 일관되게 비열을 인쇄하지 않는다는 **구조를 확정**했으며,
테이프 밀도 0건은 요청 밖에서 관찰한 12건으로 **기존 DB 17건을 교차검증**했다(불일치 0).

**어디를 그만 파야 하는지가 어디를 더 파야 하는지만큼 중요하고,
이번엔 그 판단이 다음 배치의 방향을 세 번 바꿨다.**

### 13.4 갈래별 채굴 수율을 실측해 표적 선정의 근거로 쓴다

40차 이후로는 "어디가 잘 나오나"를 감이 아니라 **실측 수율**로 정한다(§450).
그리고 그 수율표가 다음 파동의 표적 선정 근거다.

같은 계열로 **광맥과 막다른 길이 둘 다 지도에 오른다.**

- **광맥** — 학회 자료집 · 저널 SI · 봇차단 벤더 세 조달 경로를 지도에 올렸다(§518).
  벤더 SDS 9절이 용제 밀도의 출구다(§500).
- **막다른 길** — 사파이어 실측은 **결정성장 논문으로는 세 번 다 못 얻었다.
  표적을 바꿔라**(§441). 커버글라스 벤더 수치의 대부분은 물성이 아니라 소자 시험이다(§473).
- **그리고 "이미 채굴됨"은 논문이 아니라 표 하나를 뜻할 수 있다**(§506).
  한 논문에서 표 하나를 캤다고 그 논문이 소진된 것이 아니다.

## 14. 신뢰도 고도화 경로 — 가정값을 실측으로 갈아 끼우는 구조

### 14.1 네 단 사다리

```
   tier4  근거 있는 가정 ─┐
        (계열 통계 중앙값, 공표된 추정식)   assumption:true + method:estimated
                          ↓  실측이 들어오면 대표값 선택에서 자동으로 밀린다
   tier3  계열 대표값 ────┤
        (같은 계열 다른 제품의 실측, 2차 인용, 등급 불일치 대체)
                          ↓
   tier2  핸드북·표준 ────┤
        (MMPDS · ASM · NIST · CDA · ISO/ASTM)
                          ↓
   tier1  그 제품 실측 ───┘
        (벤더 TDS · 그 재료를 시험한 논문)
```

**갈아 끼우는 데 사람 손이 필요 없다.** 대표값 선택이 tier를 우선 순위로 쓰므로
tier1 행이 하나 들어오는 순간 조회·비교·DYNA 카드가 전부 그쪽을 쓴다.
tier4 행은 삭제하지 않고 남긴다 — **불확실성 범위와 이력을 보존하기 위해서다.**


**갈아 끼우기가 실제로 일어났다는 증거가 이번 갱신에 있다.**
tier1 비율이 13차의 **44.8%에서 61.4%**로 올랐고 tier3은 26.4%에서 19.2%로 줄었다(§2.1).
값이 늘어난 것만이 아니라 **계열 대입으로 닫았던 칸이 그 제품 자신의 인쇄값으로 갈아 끼워진 것**이다.
표적을 "논문의 계열값"에서 "벤더 시트를 직접 연다"로 바꾼 결과다(브리프 §127·§585).

### 14.2 지금 tier4가 몇 건이고 어디에 몰려 있나

tier4는 **4,496건(10.9%)**이다. 그중 `assumption: true` 표지를 가진 것이 **4,404건**이고,
나머지 92건은 전부 `computed`로 **가정이 아니라 계산·유도값**이다.

### 14.3 포아송비 — 가정값의 실제 불확도가 측정된 사례

포아송비 tier4 317건이 **여덟 개 숫자에서 복제**돼 있었고 `0.490` 하나가 106건이었다(68장).

그런데 **Isola가 모든 라미네이트 TDS에 ν를 length/cross로 ASTM D3039 실측으로 인쇄한다.**
실측 스펙트럼이 **FR408HR 0.137 ~ I-Tera MT40 0.234**다.
**"직물유리 적층판 ν=0.183"이라는 클래스 가정 하나가 20건에 복제돼 있는데 실제 폭이 0.13~0.23이다.**

같은 파동에서 두 가지가 더 드러났다.

- **3M VHB 아크릴 폼 테이프의 ν는 0.49가 아니라 0.35다.** 3M 공식 TDS의 2018·2019 개정판에
  `Poisson's Ratio 0.35` 행이 있는데 **3M이 2022년 이후 개정판에서 이 행을 삭제**했다.
  폼 테이프 8종의 0.30/0.49 가정이 전부 틀렸다.
- **PA6-GF30이 등방이 아니었다.** 유동방향 0.43/0.39, 직교방향 0.22/0.27로
  **2배 방향 편차**를 단일 가정값 0.35가 덮고 있었다.

**교훈은 tier4를 tier1로 갈아 끼우는 일이 "정밀도 개선"이 아니라
"틀린 값의 교체"인 경우가 있다는 것이다.**

### 14.4 고도화의 다음 표적

1. **DIF 450건** — 이것이 지금 1순위다. 낙하·충격의 **실측 기준 준비율 8.1%**를 혼자
   누르고 있다. 무차원 계열 대입이라 자릿수 모순은 없지만 **그 재료의 값이 아니다.**
   OA 밖(핸드북·벤더 시험보고서)을 봐야 한다.
2. **포아송비 410건** — Isola처럼 ν를 인쇄하는 벤더를 더 찾는 것이 그다음이다.
   다만 **OLED 저분자는 실측이 문헌에 존재하지 않는다** — 대표 나노압입 연구조차
   ν를 몰라 `E/(1−ν²)` reduced modulus로만 발표한다.
   그리고 §6.1(가)가 확인했다 — **packaging 시트 7장 중 ν를 찍은 것이 0장**이다.
3. **열전도율 307건 · 비열 205건** — CCL·테이프·연자성재·커버글래스는 벤더 전수 확인으로
   **구조적 부재가 확정**됐다(§585). 남은 경로는 실측 위탁뿐이다.
4. **전방사율 201건(84.1%)** — 표면 상태가 지배해서 벤더가 안 낸다.
   §6의 갈래로는 ③(벤더 구조적 부재)에 가깝다 — **표적으로 잡기 전에 그것부터 확정해라.**

## 16. 이 방법론이 틀렸던 순간들

**이 절이 이 문서에서 가장 중요하다.**
아래는 전부 우리가 세운 가설·지표·지시가 반례로 무너진 기록이다.
**자기 교정이 이 시스템의 핵심이고, 그 교정은 예외 없이 "숫자가 이상하다"에서 시작됐다.**

### 16.1 구조적 부재 22% 추정이 0.7%로 밝혀졌다 (70장)

"셀 채움 64.5%"의 천장이 100%가 아닐 것 같아 구조적 부재를 분리하려 했다.
착수 전 추정은 **"544종 중 124종(22%)이 못 채우는 재료라 8%p가 천장 아래"**였다.

**틀렸다. 재료 단위로 통째 제외해서 나온 숫자였다** — 이미 채워진 칸까지 버린 계산이다.
부재를 (재료군 × 물성) 쌍으로 선언하고 반례 검증을 붙이니 **선언 16개 중 13개가 무너졌고**
실제 구조적 부재는 **106칸(0.7%)**뿐이었다.

**천장은 100%에 가깝고, 남은 일은 내가 말한 것보다 훨씬 많다.**
앞선 파동들의 "확정된 부재" 보고는 **특정 제품을 못 찾았다**는 뜻이지
그 물성이 그 재료군 전체에서 발표되지 않는다는 뜻이 아니었다. **그걸 일반화한 것이 오류였다.**

### 16.2 지표가 자기 가정값에 속고 있었다 — 26배 큰 왜곡 (70·71장)

천장(분모)을 재려던 시도가 바닥(분자)을 드러냈다.

| | 셀 채움 | 재료 준비(구조·강성) |
|---|---:|---:|
| 당시 지표(가정 포함) | 64.5% | 61.2% |
| **tier4 제외(실측 기반)** | **46.3%** | **27.8%** |
| 차이 | **18.1%p · 2,628칸** | 33.4%p |

**구조적 부재(0.7%)를 찾으러 갔는데 그보다 26배 큰 왜곡을 찾았다.**
지표를 의심할 때는 분모만이 아니라 분자도 봐야 한다.

그리고 8차에서 그 반례 검증 장치 자체가 **자기 가정값에 속았다** —
항복강도 배치가 아크릴 폼 테이프 11종에 tier4 가정값을 넣자
"점착테이프에는 항복점이 물리적으로 없다"는 선언이 자동 은퇴했다.
반례 판정이 tier를 구분하지 않고 있었고, 그 경고는 **157종을 오탐**하고 있었다.

**방침을 바꾸면 그 방침이 기존 장치를 어떻게 흔드는지도 봐야 한다.**
"tier4로 칸을 채운다"는 결정 하나가 **부재 판정·경고·커버리지 세 곳을 동시에 흔들었다.**

### 16.3 "G가 최단 경로"라는 지시가 틀렸다 (72장)

9차 Prony 배치에 **"G부터 훑는 것이 최단 경로"**라고 지시했다.
8차에서 VHB TDS가 G를 인쇄하는 것을 봤기 때문이다.

**틀렸다 — 145종 중 자기 제품의 G를 인쇄한 벤더는 0곳**이고 G 단독으로 닫힌 것은 3종뿐이다.
반대로 **Prony 세트는 포장·디스플레이 FEA 논문 표에 계속 실린다.**
배치가 방향을 틀어 119종을 1,490행으로 닫았다.

**한 사례(VHB)에서 일반 규칙을 만든 것이 오류였다.**

### 16.4 브리프 자신의 URL이 404였다 (72장)

**지시서도 1차 자료로 취급해 검증해야 한다.**

### 16.5 오탈자 하나가 근거 1,590건을 지우고 있었다 (67장)

`ingest_agent_json.py`가 `pr.get("note")`(단수)만 읽는데
브리프의 출력 예시는 `"notes"`(복수)였다.

**근거 문구가 조용히 전부 사라졌다** — 최근 인제스트분의 **37%**, 전체로는 1,590건.

이 유실이 특히 나쁜 이유가 있다. **값은 남고 "왜 그 값인가"만 없어진다.**
무결성 검사는 값·단위·조건만 보므로 이 결함에 걸리지 않는다.
그런데 사라진 것이 이 카탈로그에서 가장 값진 부분이다 —
열 머리글을 어떻게 확인했는지, 단위를 어떻게 환산했는지, 등급이 무엇이 다른지.

3~5차 파동 산출물 38개 파일을 전부 재적재해 1,590 → 950건으로 줄였다.
(현재 952건. 남은 것은 산출 JSON이 없는 초기 파동분이라 복구 경로가 없다.)

**같은 종류의 사고가 세 번째다** — `tier` vs `quality_tier`(377건 강등),
`volume_resistivity` vs `resistivity_volume`(**존재하지 않는 키를 세고 있었다**), 그리고 이것.
**로더와 브리프의 키 이름이 어긋나면 조용히 유실된다.**

|---|---:|---|
| `computed` @ tier1 | 103 | **정당하다.** 벤더가 각주로 *"calculated value per datasheet footnote"*라 밝힌 값, 논문이 자기 시편에 피팅해 인쇄한 Prony 항 — 그 제품에 대해 인쇄됐으니 tier1이고, 계산값이니 computed다 |
| `computed` @ tier2 | 104 | **정당하다.** 인쇄된 두 수로 우리가 환산한 값을 한 단계 낮춘 것이다(tesa 61395: 20 N/cm ÷ 200 µm 두께 = 10 MPa). 기하가 개입하는 환산이라 tier1을 주지 않는 것이 보수적으로 옳다 |
| `measured` @ tier2 | 2 | **정당하다.** 다른 시료의 실측을 계열값으로 쓴 것이다 |
| `handbook` @ tier1 | 1 | 제조사(Special Metals) 자사 불리틴의 정성 등급이라 tier1이 맞다 |
| **`estimated` @ tier3** | **15** | **이것만 진짜 결함이었다.** 전부 CRC·ASM·벤더 TDS에 **인쇄된 계열값**인데 method가 estimated였다. 우리가 만든 수가 아니므로 `handbook` 14 · `measured` 1로 정정했다 |

**조합을 세는 것이 애초에 잘못된 검사 설계였다.** 조합표는 허용 목록이라 새로운 정당한
조합이 생길 때마다 오탐을 낸다. 뜻이 어긋나는 것만 잡으면 규칙이 둘로 줄어든다.

1. **`estimated`는 "우리가 만든 값"이다** → tier4가 아니면 어느 쪽이든 거짓말이다.
2. **tier4는 "우리가 만든 값"이다** → `measured`·`handbook`이면 등급이 틀렸다.

`integrity_check.py`가 이 둘을 검사한다(현재 50항목 중 둘). 앞서 지적한 `estimated` @ tier1 8건은
12차에 이미 `measured`로 정정됐다 — 전부 그 논문이 그 재료에 대해 식별한 모델 상수였다.

### 16.11 이번 갱신에서 새로 발견한 것 — 같은 수식이 세 번째 자리에 남아 있었다

§16.10(가)가 *"지표를 고칠 때는 같은 수식이 쓰인 자리를 전부 찾아야 한다"*고 적었다.
**그 문장이 세 번째로 필요했다.**

`coverage_report.py`의 해석별 표(12차)와 요약줄(13차)은 고쳐졌는데,
**물성 보유율 표에 같은 종류의 분모/분자 불일치가 남아 있었다.**

```
갱신 착수 시점                          같은 파동에 고친 뒤
   1001종 115.9%  영률                     675종  78.1%  선팽창계수(CTE)
    965종 111.7%  선팽창계수(CTE)             647종  74.9%  영률
    947종 109.6%  밀도                      642종  74.3%  밀도
    915종 105.9%  열전도율                    587종  67.9%  열전도율
```

**분모는 격자 대상 864종인데 분자가 `evidence`·`out_of_scope`를 포함한 전 재료를 세고 있었다.**
그래서 네 물성이 100%를 넘었다. **값은 멀쩡했고 표시가 틀렸다.**

이 문서는 그 사이 **§8·§14·§15의 어느 수치도 그 표에서 가져오지 않았다** —
해석별 격자(정상)와 라이브 DB 직접 질의만 썼다. 표가 고쳐진 지금도 규율은 같다.

**세 번째 재발이다.** 12차 해석별 표 · 13차 요약줄 · 54차 물성 보유율 표.
**같은 수식이 세 곳에 있었고 한 번에 하나씩 고쳐졌다.**
그리고 세 번 다 **"100%를 넘는 수가 인쇄된다"**는 같은 지문으로 드러났다 —
**지표에 상한이 있으면 그 상한을 검사로 걸어라.**

### 16.12 그리고 이 문서 자신이 41개 파동 동안 안 고쳐졌다

이 문서의 13차판은 **기준일이 2026-08-10**이었고 §5.2에
*"지금은 그 척도가 무력하다 … 이 척도는 스스로 수명을 다한다"*고 **예고까지 적어 두었다.**
그 예고는 실현됐는데(§7.2) **문서는 41개 파동 동안 갱신되지 않았다.**

그동안 `COLLECTION_BRIEF_CORPUS.md`는 §464에서 §599까지 136절이 쌓였다.
**함정 지도는 자랐고 방법론 문서는 멈춰 있었다.**

교훈이 §13.1과 같은 것이다 — **실패를 적는 곳과 방법을 적는 곳이 다르면,
방법을 적는 곳이 먼저 낡는다.** 브리프는 파동마다 쓰이니까 갱신되고,
방법론 문서는 아무도 안 열면 안 낡은 것처럼 보인다.

**규율 — 이 문서의 기준일과 라이브 DB의 최신 파동 번호가 세 파동 이상 벌어지면
그 자체가 결함이다.**

### 16.13 요지

이 절의 사례들에는 공통 구조가 있다.

1. **숫자가 이상하다는 감각에서 시작한다** — "천장이 100%일 리 없다", "0.0%는 이상하다".
2. **가설을 반증 가능한 형태로 만든다** — 부재를 (재료군 × 물성) 쌍으로 선언하고 반례를 센다.
3. **반례가 하나라도 나오면 선언이 무너지게 자동화한다** — 사람이 기억할 필요가 없다.
4. **그리고 무너진 기록을 남긴다** — 그래야 같은 가설을 다시 세우지 않는다.

**틀렸다는 것을 문서에 쓰는 것이 이 방법론의 산출물이다.**
카탈로그의 신뢰도는 "우리가 옳았다"에서 오지 않고
**"틀린 것을 어떻게 찾아냈는가"가 기록돼 있다는 데서 온다.**

### 재료별 남은 빈칸 분포 (§7.2)

python3 - <<'PYX'
import io, sys, contextlib
from collections import Counter, defaultdict
sys.path.insert(0, "backend/scripts/catalog")
with contextlib.redirect_stdout(io.StringIO()):
    import coverage_report as CR
    c, mat, own, meas = CR.load()

def unfill(mid):
    nm = mat[mid][0].lower()
    ks = set()
    for matcher, keys, _ in CR.UNFILLABLE:
        if any(w in nm for w in matcher):
            ks |= keys
    return ks

miss = defaultdict(int)
per_an = defaultdict(dict)
for name, req, alts, filt, _ in CR.ANALYSES:
    for m in CR.scope(mat, filt):
        ks, uf, n = own.get(m, set()), unfill(m), 0
        n += sum(1 for k in req if k not in ks and k not in uf)
        for g in alts:
            flat = {x for alt in g for x in alt} if (g and isinstance(g[0], tuple)) else set(g)
            if not CR.grp_ok(ks, g) and not flat <= uf:
                n += 1
        if n:
            miss[m] += n
            per_an[name][m] = n

d = Counter(miss.values())
print("빈칸 있는 재료", len(miss), "/", len(mat), " · 1칸 부족", d[1], "종")
for name in per_an:
    cc = Counter(per_an[name].values())
    print(f"  {name:16s} 남은 {len(per_an[name]):4d}  1칸 {cc[1]:4d}  2칸 {cc[2]:3d}")
