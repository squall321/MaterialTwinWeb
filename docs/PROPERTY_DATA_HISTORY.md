# 물성 데이터 구축 히스토리

MaterialTwin 카탈로그가 **0 → 5,963 물성값** 으로 채워진 과정과, 그 과정에서
정한 규칙·발견한 함정을 기록한다. 커밋 단위 변경은 git log에 있으므로, 여기에는 **왜 그렇게
했는지**와 **다시 할 때 알아야 할 것**만 남긴다.

최종 상태(2026-08-03): 재료 313종 · 물성값 7,574(실측 3,927 · 핸드북 1,383) · 출처 967(DOI 223) ·
물성 정의 109개 중 104개에 값 존재 · **추정값만 있는 재료 0종** · **출처 없는 값 0건**.
DYNA 입력 커버리지 — 밀도 91.2% · 영률 87.5% · CTE 91.2%.

## 단계별 경과

### 0단계 — 스키마 (커밋 `31a668c`)
`property_definition`(91개 taxonomy) · `source`(프로비넌스) · `property_value`(값+조건+등급) 3테이블.
설계 결정 하나가 이후 전부를 좌우했다 — **출처 없는 값은 저장 자체를 거부**(`register_property`가
source_doi/url/title 중 하나를 요구). 덕분에 끝까지 "출처없음 0"을 유지했다.

### 1단계 — 스마트폰 재질 카탈로그 (193종 / 1,429값)
AIDataHub의 HW 에이전트 도메인을 커버리지 체크리스트로 삼아 스마트폰 내부 재질을 수집.
그레이드 단위 충실도를 목표로 함(예: "광학 플라스틱"이 아니라 `APEL 5014CL (COC, Mitsui)`).

### 2단계 — 조회 수단 (`0c77c4c` ~ `ecd8b9f`)
데이터가 있어도 볼 수단이 없으면 죽은 데이터다. 순서대로 카탈로그 UI → 재료 비교(최대 12종)
→ Ashby 산점도 → LS-DYNA 카드 출력. **웹과 MCP가 같은 코어를 공유**(`catalog_compare.py`,
`dyna_export.py`)해 화면과 에이전트 답이 갈리지 않게 했다.

### 3단계 — 출처 실체화 (`ea1ba75`, `c0ac85a`)
journal 출처 174건 중 DOI가 12건뿐이었다. CrossRef API로 제목 검색 → **DOI 6% → 100%**.
지어내지 않기 위해 세 겹 필터: 제목 유사도 ≥0.92 + 원저널/학회 논문 종류 + **인용수**.
인용수 기준이 결정적이었다 — 재수록본(World Scientific 챕터, 인용 9)이 원저(Nature Materials
`10.1038/nmat732`, 인용 2797)를 밀어내는 걸 막았다.

### 4단계 — 해석 입력 물성 (`cc73ced`, `9eadc69`, `3aa52ea`)
DYNA 카드에 필요한 6종(밀도·영률·포아송비·비열·열전도·CTE)이 19~89%로 구멍이 많았다.
계열 규칙으로 99~100%까지 채우되 **tier4(계열 추정)로 정직 표기**.
이어서 흡습률·방사율·아웃가싱 등 비-DYNA 물성도 보강.
σ-ε 곡선은 스칼라에서 **합성**하되 그래프에 `[실측]`/`[합성]`을 명시하고 출처를 함께 렌더.

### 5단계 — 추출 도구 (`62d934d`)
업체 데이터시트가 Illustrator로 만든 **이미지 전용 PDF**인 경우가 많아 `pdftotext`로는 0자였다.
- `scripts/catalog/extract_datasheet.py` — 텍스트 레이어 우선, 비면 300dpi 렌더 후 OCR 폴백
- `scripts/catalog/digitize_curve.py` — 그래프 이미지 → 좌표 CSV
설치 직후 Kuraray FCCL 브로슈어(텍스트 0자)를 OCR로 뚫어 물성표 전체를 얻었다.

### 6단계 — 벤더 병렬 수집 (`20c0204` ~ `18c8e7d`)
10개 에이전트를 벤더 영역별로 나눠 투입. **에이전트는 DB에 직접 쓰지 않는다** —
SQLite 락 경합을 피하고 등록 전 검토 지점을 만들기 위해 JSON으로 내놓게 하고,
메인이 `scripts/catalog/ingest_agent_json.py`로 검증 후 직렬 등록.
벤더 60곳 이상 · 1,662건 실측 확보.

### 7단계 — 논문 기반 보강 (`0ec5b02` 외)
실측 0건 재료가 137종 남았는데 대부분 반도체·세라믹·MEMS로 **애초에 벤더 데이터시트가 없는**
것들이었다. 전략을 논문(DOI)으로 전환 → 137 → 84종. 마지막 빈 물성 7개까지 개통해 **91/91 달성**.

### 10단계 — 화면이 데이터를 못 따라간 것 (`4d80f32` ~)

물성만 잔뜩 늘리는 동안 **화면은 시험 중심 그대로**였다. 재료가 193 → 295로 늘고
신규 재료는 전부 물성만 있는데, 재료 목록이 최신순(`id desc`)이라 첫 페이지가
전부 신규 재료로 채워졌고 들어가면 "시험 데이터가 없습니다"만 떴다. 앱 전체가
빈 것처럼 보였지만 시험 73건·곡선 73·피팅 171은 멀쩡했다.

- 재료 상세: **시험 유무와 무관하게** 물성 섹션을 항상 렌더. 시험이 있으면 곡선·피팅
  아래에 물성이 이어지고, 없으면 물성만 나온다. 둘 다 없을 때만 업로드 안내
- 재료 목록: "시험 n"/"물성 n" 배지 + `has_tests` 필터
- 카탈로그 상세 ↔ 재료 상세 교차 링크
- **교훈: 데이터를 크게 늘렸으면 그 데이터가 화면에서 어떻게 보이는지 확인할 것.**
  집계 필드를 목록에 넣을 때는 페이지 내 재료만 group by로(N+1 금지).

**정합성 점검 14항목**(마무리 때 매번 돌릴 것) — 출처 없는 값 / 끊어진 참조 /
정의 없는 키 / 값·텍스트 모두 없음 / 단위 불일치 / tier 범위 / method 어휘 /
출처 kind 어휘 / **category 어휘** / 물성값 0인 재료 / 추정만 있는 재료 /
제목 없는 출처 / **journal인데 DOI 없음** / **conditions가 dict 아님**.
마지막 세 개가 실제로 걸렸다. 이후 **고아 시편**과 **항복 ≤ 인장** 검사를 더해 16항목이 됐다.

**항복 > 인장이 10건 나온다.** 값 각각은 출처가 있는데도 조합이 물리적으로 불가능한 이유는,
**대표값을 물성마다 독립으로 고르기 때문**이다. PC/ABS는 항복이 CYCOLOY C2950, 인장이
Cycoloy C1200에서 왔고, 동박은 항복이 IPC-4562A 추정치인데 인장은 18 µm 실측이다.
곡선 합성은 이 조합을 그대로 쓰면 안 되므로 `curve_synth._consistent_yield_uts()`가
같은 재료 안에서 항복 ≤ 인장을 만족하는 최선 조합으로 바꾸고 그 사실을 노트에 남긴다.
근본 해결은 **결합된 물성을 같은 출처에서 함께 뽑는 것**인데, 대표값 규칙 자체를
바꾸는 일이라 아직 하지 않았다.
- `category`에 어휘 밖 값(`organic`·`semiconductor`·`liquid`)이 16건 — DB에 CHECK가
  없어 MCP 경로로 들어왔다. **어느 분류 칩에도 안 잡혀 화면에서 사라지고 있었다.**
- DOI 없는 `journal` 6건 — arXiv 2건은 DataCite에 등록된 DOI(`10.48550/arXiv.*`)를
  제목 대조 후 부여, 학회 자료집·기업 기술지 4건은 색인 저널이 아니라 `other`로 재분류
- `conditions`가 dict가 아닌 서술 문자열 61건 — 조건 비교·중복 판정이 무력화되므로
  `{"detail": ...}`로 감쌌다

### 9단계 — 등급 정규화와 마지막 빈 칸 (`eb0cc7e` ~)

수집이 끝난 뒤 **같은 성격의 값이 두 등급에 갈려 있는 것**이 드러났다.
벤더가 자기 제품에 인쇄한 시험값이 기존에는 tier1인데, 8단계 수집에서는 tier3으로 들어갔다.
대표값 선택이 최저 tier를 고르므로 조회 결과가 갈렸다.
`normalize_tiers.py`로 3단계 판정 — 데이터시트 66쌍·논문 103쌍을 전수 대조해 귀속이 맞는
630건만 승격했다. tier1 1,957 → 3,430.

그 뒤 마지막 남은 빈 물성 키(`interface.surface_energy`)를 접촉각 논문으로 열어
**105/105 달성**. 그래프로만 있던 것(Tatsuta SE), 문서를 못 열었던 것(ACF 벌크물성),
쿼터로 끊겼던 것(본딩와이어·표면처리·이미지센서)까지 회수했다.

### 8단계 — 추정값 몰아내기 (`29ecf57` ~ `9f46774`)

"근거 있는 값이 하나도 없는 재료"를 0으로 만드는 것이 목표였다. 84종 → **0종**.
네 갈래로 나눠 동시에 밀었다.

**(a) 노트에 갇힌 값 구조화 (74건)** — 박리력·차폐효과·열저항은 taxonomy에 대응 키가 없어
그동안 `notes` 문자열로만 보존돼 있었다. 조회·비교·DYNA 출력 어디에도 안 잡히는 죽은
데이터였다. `interface` 도메인을 신설하고 12키를 추가(91 → 103)해 SI 환산 후 정식 등록.

**(b) 표준 합금 (341건)** — SUS·Al·Ti·강·황동·Mg·W 30종은 애초에 규격·공인 DB에 값이
있는데도 계열 추정만 달려 있었다. ASTM/JIS 최소보증치는 tier2(standard), AZoM·MakeItFrom은
tier3(database)로 **구분해** 등록. 실측이 아니므로 tier1은 쓰지 않았다.

**(c) 벤더 우회 확보 (137건)** — "TDS가 로그인 뒤에 있다"고 포기했던 것들. 대부분
**포기가 이르렀다**. Corning은 UA+Referer로 403이 뚫렸고, Dexerials ACF는 TDS가 아니라
제품 페이지에 도전입자경·본딩 조건이 있었으며, 3M OCA 점탄성은 TDS가 아니라 폴더블
백서 Table 1과 논문에 있었다. Envalior는 CAMPUS 출력물을 재배포하는 대리점 PDF로.

**(d) 논문·제품지정·디지타이즈 (493건)** — 벤더 문서가 존재하지 않는 부류(OLED 유기층·
포토레지스트·박막)는 논문으로, 부류 이름뿐이던 재료 19종("OCA UV Cured" 등)은 실제 상용
제품을 지정해서, 그래프로만 공개된 것(Tatsuta 차폐효과)은 `digitize_curve.py`로.

## 정한 규칙 (다시 할 때도 지킬 것)

1. **지어내지 않는다.** 문서·논문에 실제 있는 수치만. 빈 게 틀린 것보다 낫다.
2. **등급을 정직하게.** 다만 tier의 실제 기준은 "문서의 종류"가 아니라 **"값의 성격"** 이다.
   - **tier1** — 특정 제품·시편에 대해 **문서에 인쇄된 실제 시험값**.
     벤더 TDS든 논문이든 상관없다(현재 tier1 1,957건 중 1,662건이 벤더 TDS 유래).
   - **tier2** — 핸드북·규격 최소보증치·공인 DB.
   - **tier3** — 계열/클래스 대표값, 2차 인용, 좌표 추출값.
   - **tier4** — 계산·유도·추정.
   계열 대표값에는 "정밀 설계 시 업체 데이터시트로 대체 권장" 노트를 단다.

   `method`는 **measured / handbook / computed / estimated** 넷만 쓴다.
   `datasheet`는 방법이 아니라 출처 종류다(한때 method로 쓰여 902건이 섞여 있었다).

   정리 후 method×tier는 아래 조합만 남는다 — 다른 조합이 나오면 어딘가 어긋난 것이다.
   | method | tier | 뜻 |
   |---|---|---|
   | measured | 1 | 문서에 인쇄된 그 재료의 시험값 |
   | measured | 3 | 다른 시료를 측정한 클래스 대표값 |
   | handbook | 2 | 핸드북·규격 최소보증치 |
   | handbook | 3 | 2차 DB(AZoM 등), 논문이 인용한 문헌값 |
   | computed | 3 | 그래프 디지타이즈(원 데이터는 실측, 좌표 오차만 얹힘) |
   | computed | 4 | 유도·시뮬레이션 |
   | estimated | 4 | 계열·등가근사 |

   판정은 `scripts/catalog/normalize_tiers.py`가 노트·조건의 표지로 자동 분류하고,
   애매한 것만 스크립트 안 `MANUAL` 목록으로 개별 판정한다(재현 가능하게 남길 것).
3. **조건 없는 값은 의미가 없다** — 아래는 조건 없으면 기록 금지.
   - Dk/Df → 주파수
   - 이방성 물성(방열 시트·PGS·결정) → 방향/결정방위
   - 소광계수·분광방사율 → 파장
   - 크리프율 → 응력·온도
   - 확산계수 → 확산종·온도
   - 박막·소결재 → 두께·어닐·기공률 (없으면 벌크값과 구분 불가)
4. **범위값은 중간값을 만들지 않는다.** 하한만 쓰거나 min/max로 분리.
5. **단위는 SI로.** 특히 비율 물성(연신율·흡습률)을 퍼센트로 넣으면 100배 오류.
6. **유도값은 실측으로 위장하지 않는다.** SAC305 크리프율은 Norton 상수에서 계산한
   값이라 tier4·`method=computed`로 낮추고 유도 과정을 노트에 남겼다.

## 실제로 잡은 데이터 오류 (같은 함정 재발 방지)

| 오류 | 실체 | 영향 |
|---|---|---|
| **파단연신율 퍼센트 혼입** | 같은 단위 `1`에 150(%)과 0.72(비율)가 공존 | 비교표·Ashby가 100배 왜곡. 39건 정규화 |

| **3M OCA 8211 값이 8171에** | 논문이 측정한 제품과 등록 대상이 다름 | Kapton과 같은 오귀속. 별도 재료로 분리 |
| **3M 4411N 박리력 1.75배 불일치** | 원문 `14.6 N/cm`와 `25.6 lb/in`이 서로 안 맞음 | EU판 TDS를 직접 받아 `13.4 N/cm`(스테인리스·프라이머 없음) 확인 → 미국판(알루미늄+프라이머)과 **별개 측정**이었고 lb/in 병기가 오기 |
| **벤더 카탈로그를 tier2로** | 데이터시트 232건이 핸드북급으로 등재 | 신뢰등급 인플레. tier3로 정정 |
| **PGS 인장 0.1 MPa가 이상치로 보임** | 실은 **두께방향(Z) 층간 강도**. 면내의 1/300 | 이상치가 아니라 이방성. 조건에 `axis`가 있었기에 판별됐다 |
| **ACF 도전입자경을 결정립 키에** | `structure.grain_size`에 등록 | PZT와 같은 오염. `structure.particle_diameter` 신설 |

**dedupe의 함정** — 세 번 물렸다.
1. 조건 표기만 다른 같은 값은 병합해야 하지만 `Isola Dk 3.92 @5GHz`와 `@10GHz`는 별개
   측정이다. **정규화 조건이 다르면 병합하지 않는다.**
2. 그런데 조건이 `A/A/B`로 섞인 그룹에서 정보량 최고인 `B`를 keeper로 잡으면
   진짜 중복인 `A·A`를 놓친다. **조건 서명별 버킷으로 나눠서** 각각 병합해야 한다.
3. 이방성 방향 표기가 `axis`/`direction`으로, 값도 `in-plane`/`in-plane (X,Y)`로 갈린다.
   키와 값 양쪽을 정규화해야 같은 측정으로 인식된다.

**인제스트 검증기의 함정**: "기존 tier1 실측을 덮지 않는다"는 규칙이 **조건이 다른 별개
측정까지 막았다.** 조건 서명이 일치할 때만 차단하도록 고쳤다. 신규 키에는 물리 범위를
걸어두면 범위 자체가 단위 검산이 된다 — DOL을 µm 원값으로, CS를 MPa 원값으로,
TCR을 ppm/K 원값으로 넣으면 등록 단계에서 걸린다.

**적재가 멱등이라 측정이 조용히 사라진다**: `upsert_property_value`는
(재료·물성·출처·조건)에 멱등이다. 조건이 같고 값만 다르면 나중 것이 앞의 것을 **덮는다**.
3M Viscoelastic 112P05 박리력이 112P02와 시험조건이 같아 이렇게 사라져 있었다 —
그레이드가 `conditions`가 아니라 `note`에만 있었기 때문이다.
**한 제품군의 여러 그레이드를 한 재료에 담을 때는 `grade`를 반드시 conditions에 넣어라.**
지금은 인제스트가 충돌을 감지해 덮어쓰기 대신 거부하고 사유를 보고한다.

## 파이프라인 (`scripts/catalog/`)

```
에이전트 (WebSearch → extract_datasheet.py → JSON)
   ↓  DB 직접 쓰기 금지
ingest_agent_json.py  ← 6단계 검증
   ① taxonomy에 있는 key인가
   ② 단위가 정의와 일치하는가
   ③ 출처(url/doi/title)가 있는가        ← 없으면 거부
   ④ 물리적 범위 내인가                  ← 밀도·PR·연신율 등 28개 키
   ⑤ 비율 물성이 1을 넘지 않는가          ← 퍼센트 오입력 차단
   ⑥ 기존 tier1 실측을 덮지 않는가        ← 단, 조건이 다르면 별개 측정이므로 통과
   ↓  --apply
라이브 DB → merge_sources.py → dedupe_values.py → 백업
```

실제 에이전트 출력에서 드러나 방어 처리한 형식 편차: 문자값(UL94 `"V-0"`),
`value_text` 별도 필드, `source.kind: "paper"`(DB 제약 밖), `category: "세라믹"`,
`new_material`이 dict 아닌 문자열, 이중 인코딩된 `conditions`.

**에이전트에게 키 이름을 불러줄 때는 DB에서 확인시켜라.** 그럴싸하지만 없는 키를
지어낸다 — `thermal.glass_transition_temp`(실제는 `thermal.glass_transition`),
`thermal.expansion_coefficient`(→ `expansion_linear`), `mechanical.poissons_ratio`
(→ `poisson_ratio`), `electrical.resistivity`(→ `resistivity_volume`).

**병렬 수집 시 산출 파일을 반드시 확인하라.** 에이전트가 하위 에이전트를 낳고 결과를
병합하지 않은 채 끝나는 경우가 있다. 재료명·키·값으로 DB와 대조해 회수해야
50건이 조용히 사라지지 않는다. 여러 세션이 같은 스크래치패드를 쓰면 남의 파일을
병합 대상에 넣지 않도록 파일명을 명시적으로 고정할 것.

- **라미네이트 밀도 10종** — FR-4 계열 벤더(Isola·ITEQ·TUC·Panasonic)는 **밀도를 아예
  공표하지 않는다.** 구성(유리포 종류 × 수지함량)에 따라 달라지기 때문이다.
  실제로 확보된 것들은 전부 조성이 고정된 제품(Rogers·Taconic PTFE계)이거나
  SDS 9항(Shengyi·Nan Ya) 또는 철도 화재시험 성적서(Isola 370HR·IS400)에서 나왔다.

  **산출 시도와 그 한계**: Isola는 Dk/Df 표에 구성(유리포·수지함량·두께)을 공개한다.
  `ρ = W_glass·n / ((1−RC)·t)` 로 계산할 수 있고, 같은 유리포의 수지함량 2점을 쓰면
  혼합법칙으로 수지·유리 밀도를 역산할 수도 있다. I-Tera MT40으로 시험한 결과
  유리 면밀도의 스타일 내부 편차가 0.7~2.3%로 맞았고, 앵커를 넣자 3313이 통용
  규격값 81 g/m²에 0.4% 이내로 독립 일치했다. **방법은 옳다.**
  그러나 유리포 규격 면밀도를 1차 문서에서 확보하지 못해(IPC-4412는 유료) 절대
  스케일을 고정할 수 없었고, 기억에 의존한 수치를 쓰는 것은 규칙 위반이라 중단했다.
