# 커버리지 정직화 — 체크리스트

목표 — 커버리지에 **구조적 부재**를 분리해, "채울 수 있는 칸 대비"와 "전체 대비"를 둘 다 보인다.

- [x] 1. `UNFILLABLE` 선언 — (재료 이름 매처 × 물성 키/택일군, 사유, 확인한 파동)
      → 검증: 각 항목이 `docs/BLOCKED_SOURCES.md` 또는 `PROPERTY_DATA_HISTORY.md`에
        근거를 갖는다. 근거 없는 항목 0
- [x] 2. `coverage_report.py`가 `유효 채움`(구조적 부재 제외 분모)을 함께 산출
      → 검증: 두 지표가 나란히 출력되고, 부재로 뺀 칸 수가 표시된다
- [x] 3. 부재로 선언한 칸에 **실제 값이 있으면 경고** — 선언이 틀렸다는 뜻이다
      → 검증: 값이 있는데 부재로 선언된 칸을 세어 0이 아니면 목록을 찍는다
- [x] 4. `build_coverage_docx.py`·`build_stats_xlsx.py`가 새 지표를 반영
      → 검증: 재생성 후 두 지표가 문서에 나온다
- [x] 5. 회귀 테스트
      → 검증: `pytest` 통과
- [x] 6. 이력에 **"이 상승은 정의 변경이지 수집 성과가 아니다"** 명시
      → 검증: `PROPERTY_DATA_HISTORY.md`에 전후 수치가 둘 다 기록된다

## 성공 기준

다음 파동을 계획할 때 **"남은 일이 실제로 몇 칸인가"**에 답할 수 있다.
지금은 5,150칸이 비어 보이지만 그중 몇이 원리적으로 못 채우는 칸인지 알 수 없다.

## 결과 — 예상과 반대였다

**가설이 틀렸다.** 착수 전 나는 "544종 중 124종(22%)이 구조적 부재라 8%p는 못 채운다"고
추정했다. 그 추정은 **재료 단위로 통째 제외**해서 나온 것이라 이미 채워진 칸까지 버린
잘못된 계산이었다.

반례 검증을 붙이니 실제 구조적 부재는 **106칸(0.7%)**뿐이다. 선언 16개 중 13개가
반례로 무너졌다 — 테이프 CTE 반례 29종, 영률 25종, 라미네이트 비열 15종.
**천장은 100%에 가깝고, 남은 일은 내가 말한 것보다 훨씬 많다.**

## 대신 진짜 문제가 드러났다 — tier4 가정값이 칸을 채운 것으로 세어진다

| | 셀 채움 |
|---|---:|
| 현재 지표(가정 포함) | 64.5% |
| **tier4 제외(실측 기반)** | **46.3%** |
| 차이 | **18.1%p · 2,628칸** |

해석별로는 폴더블 벤딩 66.2 → 38.8%, 구조·강성 72.8 → 48.4%, 워피지 70.5 → 47.9%다.
재료 준비율은 더 크게 갈린다 — 구조·강성 61.2 → **27.8%**.

**구조적 부재(0.7%)를 찾으려다 그보다 26배 큰 왜곡을 찾았다.**
지표에 `실측기반` 열을 넣어 둘을 나란히 보이게 했다.
