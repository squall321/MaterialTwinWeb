# 시험장비 편입 — 결정 노트

작업 중 내린 결정과 그 이유. 다음 세션이 다시 유도하지 않도록 계속 덧붙인다.

## 2026-08-15 · 스키마

**표를 둘로 했다.** `instrument` + `instrument_capability`.
측정법(기법·규격)을 별도 표로 빼지 않았다 — **한 능력행의 속성**이지 독립 개체가 아니다.
기법이 재사용되는 것처럼 보이지만(`레이저 플래시법` 이 여러 장비에), 그 문자열을 정규화해서
얻는 것이 없다. 조회는 `group by technique` 로 충분하다.

**`UniqueConstraint(instrument_id, property_key, technique)`.**
같은 장비가 같은 물성을 **두 기법**으로 재는 경우가 실제로 있다(열전도율 — 레이저 플래시 대 핫디스크).
기법을 키에 넣지 않으면 그 둘이 서로를 덮어쓴다.

**`mapping_confidence` 를 둔 이유.**
카탈로그는 우리 `property_key` 를 모른다. `Thermal diffusivity → thermal.diffusivity` 는 자명하지만
`Mechanical properties` 같은 항목은 아니다. **매핑은 우리 판단이므로 값과 분리해 표시**한다.
애매하면 아예 안 잇는 게 원칙이고, 그래도 남는 회색지대를 `medium`/`low` 로 표시한다.

**카탈로그 PDF 는 `source(kind='datasheet')` 로 넣고 `local_path` 로 dedup 한다.**
제목으로 합치지 않는다 — 같은 시리즈 브로슈어가 제목만 조금씩 다르게 인쇄되는 일이 흔해서
제목 dedup 은 **서로 다른 카탈로그를 뭉친다**. 값 수집에서 겪은 중복 폭발(브리프 22번)의
반대 방향 위험이다.

## 2026-08-15 · 적재기 거부 규칙

값 수집의 규율을 그대로 옮겼다. 테스트로 고정했다(`test_metrology.py`).

- **범위에 단위가 없으면 거부.** 숫자만 있는 범위는 값이 아니다.
- **범위 역전(`min > max`) 거부.** 열 밀림의 신호다.
- **상한만 있는 것은 정상.** `up to 1100 °C` 는 `range_max` 만 채운다 —
  **하한을 0 으로 채우면 그건 우리가 지어낸 값이다.**
- **미정의 `property_key` 거부.** taxonomy 를 우회해 키가 생기면 안 된다.

## 2026-08-15 · API 설계

**`/by-property` 는 기법으로 묶어서 낸다.**
사용자의 질문은 "어느 장비가 있나" 가 아니라 **"어떻게 재나"** 다.
같은 기법을 하는 장비 여럿은 **선택지**이지 서로 다른 답이 아니다.
규격은 능력행마다 다를 수 있어 기법 묶음에서 **모아서** 낸다 — 하나로 뭉치면 거짓이 된다.

**`/coverage` 가 이 기능의 핵심 질문에 답한다** — *잴 장비가 없는 물성*.
값이 많은데 장비가 없는 것부터 정렬한다. **그게 가장 시급한 공백**이다
(문헌에서만 얻었고 우리 손으로는 못 재는 물성).

**`covered` 목록을 같은 응답에 실었다.** 화면 좌측 목록이 한 번의 호출로 완성된다 —
처음엔 장비 목록에서 키를 모아 만들었는데 **물성 이름이 없어 키가 그대로 노출됐다.**

## 2026-08-15 · 범위 밖으로 둔 것

- **PDF 원문 뷰어** — 251 MB 이고 제조사 카탈로그라 재배포 라이선스가 불명이다. **경로만 기록**한다.
- **장비 가격·납기** — 카탈로그에 없다.
- **시험소 정보** — 다른 데이터다.

## 2026-08-15 · `instrument_capability` 에 `conditions` 컬럼을 **안 넣기로 했다**

24차 R 이 짚었다 — 홀측정의 **자기장 범위**(7604 `±1.3 T` 대 9709A `±9 T`)와 온도범위,
제타전위의 **pH 2~12**, 기공직경의 `distribution_stat` 이 갈 구조적 자리가 없어 `notes` 로 갔다.

**맞는 지적인데 지금은 안 넣는다.** 카탈로그 80편이 전부 끝나서 **채울 배치가 더 없고**,
지금 넣으면 532행 중 R 의 23행만 채워진 컬럼이 된다.
`temperature_min_k`/`max_k` 는 이미 전용 컬럼이 있어 가장 중요한 축은 구조화돼 있다.

**카탈로그를 더 넣게 되면 그때 컬럼과 백필을 함께 한다.**
후보 축 — `magnetic_field_t` · `ph` · `distribution_stat` · `carrier_type` · `model`(구성모델).

## 2026-08-15 · 규격은 인쇄된 것만 넣는다 — 키 정의로 채우지 않는다

R 이 물었다. `electrical.carrier_mobility` 의 `test_standard` 가 ASTM F76 인데
LakeShore 카탈로그는 `ASTM compliance check` 라고만 쓰고 **번호를 안 찍는다.**
Litesizer 도 ISO 13099 가 아니라 ISO 22412 만 인용한다.

**능력행의 `standard` 는 비운 것이 맞다.** 키 정의의 규격은 *그 물성의 표준 시험법*이고,
능력행의 규격은 *이 장비가 그 규격을 지원한다고 인쇄했다*는 사실이다. **다른 주장이다.**
적재기에서 일괄로 채우면 인쇄되지 않은 것을 인쇄된 것처럼 만든다.

## 미해결

- **`reliability` 분류(6편)는 능력행이 0 이 정상이다** — 항온항습조는 조건을 거는 장비이지
  측정기가 아니다. 장비 목록의 완전성을 위해 레코드는 만들되 물성에 잇지 않는다.
  다만 **온도·습도 범위는 `notes` 에 남긴다** — 노화 시험 조건 설계에 쓴다.
- **화면에서 물성 카탈로그의 빈 칸 → 측정법으로 넘어가는 링크**가 아직 없다.
  체크리스트 5번의 마지막 항목이다.
